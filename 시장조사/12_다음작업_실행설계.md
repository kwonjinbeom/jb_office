## 다음 작업의 완료 상태

다음 작업 한 번이 끝났을 때 있어야 하는 것은 계정이나 완제품이 아니다.

- Codex와 사용자의 예상 작업을 30분 단위로 나눈 표
- `지금 만들 가치가 있음 / 증거가 더 필요함 / 폐기` 판단
- 바로 제작할 1~3개의 작은 실험 제안

## 작업 1 — 유료 유틸리티의 빈틈 찾기

### Codex가 할 일

1. itch.io 유료 도구 상위권을 작업 유형별로 분류한다.
2. 가격, 업데이트 시점, 지원 OS, 리뷰·댓글의 불만, 대체 제품을 수집한다.
3. Reddit, GitHub Issues, 관련 커뮤니티에서 같은 불편이 반복되는지 확인한다.
4. `기존 생태계 보조`, `파일 변환`, `검사·시각화`, `콘텐츠 제작`, `게임·스트리밍`으로 문제를 나눈다.
5. 사용자 웹개발 능력과 Codex 자동화가 실제 우위가 되는 10개를 추린다.
6. 유료 대안 또는 구매 표현이 있는 후보만 최종 카드 3개로 만든다.

### 후보 통과 조건

- 같은 문제를 말하는 독립된 신호가 3개 이상 있다.
- 적어도 하나는 실제 유료 제품·유료 의뢰·구매 표현이다.
- 핵심 가치를 한 문장과 한 화면으로 설명할 수 있다.
- 첫 버전의 핵심 동작이 하나다.
- 개인 정보·저작권 자료를 서버에 올리지 않고도 동작시킬 수 있거나 위험을 명확히 통제할 수 있다.
- 설치, 환불과 지원이 상품 가격을 잡아먹지 않는다.

### 폐기 조건

- `AI를 붙이면 신기할 것` 외에 구매 이유가 없다.
- 무료 대안이 충분하고 반복 불만이 없다.
- 특정 서비스의 비공개 API나 약관 위반에 전적으로 의존한다.
- 첫 버전부터 계정, 팀 협업, 서버, 결제, 모바일 앱을 모두 요구한다.
- 기존 상위 제품보다 나은 점을 한 문장으로 말할 수 없다.

### 사용자가 나중에 할 일

최종 카드 3개를 보고 `내가 실제로 만들고 싶은가`, `이 문제를 이해할 수 있는가`, `사용 경험이 어색하지 않은가`만 판단한다. 시장 자료 수집과 초기 구현 가능성 검토는 Codex가 맡는다.

## 작업 2 — Medium에서 인간만이 더 잘 쓰는 형식 찾기

### Codex가 할 일

1. 최근 일반 배포·추천을 받은 개인 관찰, 유머, 짧은 서사, 관계·감정 글의 형식을 조사한다.
2. 제목의 약속, 첫 문단, 길이, 장면 수, 전환, 결말과 독자 반응을 기록한다.
3. `유행 흉내`가 아니라 사용자의 관찰·감정 묘사가 차이를 만드는 주제 틀 10개를 만든다.
4. 특정 실제 인물을 노출하거나 사실을 꾸며 논픽션처럼 보이게 하는 위험을 점검한다.
5. 완성 원고가 아니라 사용자가 자기 언어로 쓸 수 있는 구성 카드 3개를 만든다.

### 후보 통과 조건

- 경험·관찰·판단이 없으면 글의 핵심이 성립하지 않는다.
- 한 문장으로 독자가 얻는 감정이나 통찰을 설명할 수 있다.
- 한 편으로도 완결되고, 반응이 있으면 시리즈가 될 수 있다.
- 애니·주식·게임 등 한 취미를 몰라도 읽을 수 있거나, 그 취미가 진짜 차별점이다.
- AI가 대부분을 작성하지 않아도 된다.

### 역할 경계

| 작업 | Codex | 사용자 |
|---|---|---|
| 주제·유사 글·정책 조사 | 주도 | 선택적으로 의견 |
| 구조·장면 순서·질문 카드 | 주도 | 확인·변경 |
| 실제 관찰·감정·핵심 문장 | 보조 | 주도 |
| 문장 편집·제목 변형·사실 확인 | 주도 | 최종 승인 |
| 가입·멤버십·세금·정산 | 안내 | 직접 수행 |

이 경계는 사람의 강점을 살리는 동시에 Medium의 AI 수익화 정책을 지키기 위한 것이다.

### 가입 시점

Medium 멤버십부터 결제하지 않는다. 사용자가 쓰고 싶은 구성 카드가 하나 이상 나오고, 첫 원고를 실제로 완성할 의사가 확인된 뒤 월 $5를 쓴다.

## 작업 3 — 원본 숏폼 IP 형식 찾기

### Codex가 할 일

1. 단순 클립·뉴스 요약·AI 슬라이드가 아닌 원본 스토리 계정을 조사한다.
2. 60~90초 안에서 훅, 상황, 감정 반전, 결말이 작동하는 형식을 분해한다.
3. 영상 하나가 글, 이미지, 음성, 캐릭터 설정으로 재사용되는 정도를 평가한다.
4. 제작 난이도와 반복 피로가 서로 다른 형식 10개를 만든다.
5. 그중 세 가지에 대해 3편씩 이어질 수 있는 파일럿 카드를 제안한다.

### 조사할 형식의 범위

- 일상에서 생길 법한 짧은 관계극
- 한 사람의 말과 속마음이 엇갈리는 이야기
- 댓글이 다음 선택을 상상하게 만드는 상황
- 동일 캐릭터가 다른 상황에서 누적되는 시리즈
- 내레이션, 대화 자막, 제한된 애니메이션, 인터랙티브 선택형
- 전혀 서사적이지 않은 독창적 관찰·아이디어형도 함께 포함

사용자의 강점 때문에 관계극만 보는 오류를 막기 위해 마지막 항목을 반드시 조사한다.

### 파일럿 통과 조건

- 첫 2초에 상황이 이해된다.
- 60초를 넘기는 이유가 있고 중간에 새 정보가 생긴다.
- 음성을 끄고도 최소한 이해되거나 자막 버전이 있다.
- 다른 영상 클립에 기대지 않고 권리를 관리할 수 있다.
- 같은 틀을 복사하지 않고도 최소 10편의 변주가 가능하다.
- 조회가 없어도 대본·캐릭터·아트·제작 도구 중 하나가 남는다.

### 첫 테스트의 규모

채널을 여러 개 만들거나 20편을 미리 쌓지 않는다. 선택된 한 형식의 파일럿 3편을 완성한 뒤, 플랫폼별 계정을 만들지 기존 계정으로 시험할지 결정한다. 교차 게시는 하되 워터마크, 길이, 화면 안전 영역과 설명문을 각 플랫폼에 맞춘다.

## 세 축을 동시에 운영하는 방법

병렬이라는 말은 세 완제품을 동시에 만드는 뜻이 아니다. 단계별로 같은 깊이까지 진행한다.

| 라운드 | 유틸리티 | Medium | 숏폼 | 사용자에게 보여줄 양 |
|---|---|---|---|---|
| 1. 증거 | 문제 10개 | 형식 10개 | 형식 10개 | 각 축 상위 3개만 |
| 2. 설계 | 클릭 가능한 흐름 | 구성 카드 | 3편 파일럿 카드 | 선택·수정 포인트만 |
| 3. 제작 | 핵심 동작 1개 | 원고 1편 | 영상 1편 | 실제 결과물 |
| 4. 공개 | 상품 페이지 | 유료 글 | 3개 플랫폼 | 가입·승인 필요 |
| 5. 판단 | 방문→구매 | 노출→읽기 | 완주·저장·공유 | 계속·수정·폐기 |

한 라운드가 끝나기 전에 한 축만 로고·브랜딩·대형 제작으로 앞서가지 않는다.

## 성과 기록 방식

### 공통

- 제작에 든 사람 시간과 Codex 작업
- 직접 비용
- 공개 URL과 공개일
- 노출, 클릭, 사용, 구매까지의 단계별 숫자
- 예상과 달랐던 반응
- 재사용 가능한 파일·코드·문장·데이터

### 유틸리티

- 상품 페이지 조회
- 데모 실행 또는 다운로드
- 결제 전 이탈
- 구매·환불·지원 요청
- 가장 많이 쓰인 기능

### Medium

- 배포·조회·읽기 시간
- 완독 또는 읽기 비율
- 회원 읽기와 수익
- 반응·팔로우
- 다음 글로 이어진 주제

### 숏폼

- 2초 이탈, 평균 시청 시간, 완주율
- 재시청·저장·공유
- 구체적인 댓글과 팔로우 전환
- 플랫폼별 같은 원본의 차이

조회 수 하나만으로 계속·폐기를 결정하지 않는다.

## 사용자에게 다시 보여줄 첫 화면

다음 조사 완료 후 대화에서는 긴 보고서를 다시 붙이지 않는다. 아래 형식의 카드 세 묶음만 먼저 보여준다.

```text
[후보 이름]
누가 왜 돈을 내는가: 한 문장
실제 증거: 두 문장
최소 공개물: 한 문장
Codex 작업 / 사용자 작업: 한 줄
가장 큰 반대 이유: 한 문장
판단: 제작 / 추가 조사 / 폐기
```

사용자가 마음에 드는 것을 고르면 세부 근거를 펼친다. 마음에 들지 않으면 해당 카드만 버리고 같은 축에서 새 후보를 찾는다.

## 바로 이어서 할 첫 작업

**세 축의 후보 카드 9개를 만드는 증거 조사**부터 시작한다. 상품 구현, 채널 개설, 고객 연락, 결제와 공개는 하지 않는다. 이 조사에서 특히 유틸리티 구매 문제를 가장 깊게 보고, Medium과 숏폼은 형식·정책·사람 개입량을 같은 깊이로 비교한다.

이 순서라면 창작으로만 좁아지지 않으면서도, 과거처럼 빠른 의뢰 하나에 전체 방향이 잠기지 않는다.
