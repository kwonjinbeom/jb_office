# AI가 완성 원고를 만드는 장르별 자동화 템플릿

설계일: 2026-10-15. [확정 요구](00_요구사항.md)와 [실제 글 14편 분석](../../../시장조사/16_포스팅자동화_실제글분석_2026-10-15.md)을 바탕으로 한다. **아래 구성은 AI의 제작 규칙이다. 사용자가 빈칸을 채우는 글쓰기 양식이 아니다.** 아직 생성 기능에 적용한 구현은 아니다.

## 1. 한 편의 완성 기준

| 묶음 | AI가 준비하는 것 |
|---|---|
| 글 | 최종 제목 1개, 필요하면 대안 2개, 본문, 짧은 소개·태그 |
| 관점 | 이 글이 말하려는 것, 대상 독자의 조건, 다른 선택이 맞는 경우 |
| 이미지 | 실제 사용할 파일 또는 사용 가능한 이미지, 본문 위치, 설명·출처·사용 범위 |
| 이미지 멘트 | 사진에서 볼 지점·짧은 반응·본문과의 연결. 본문을 반복하지 않는 캡션 |
| 말투 | 카테고리와 사용자의 수정 이력에 맞는 문장, 호흡, 농담·이모티콘 |
| 확인 자료 | 사실에 필요한 원문·확인일·경험 근거. 본문에 필요한 출처만 자연스럽게 표시 |
| 게시용 결과 | 티스토리용 본문과 이미지 묶음. 미준비 항목은 별도 짧은 상태로 표시 |

이미지 위치 설명만 있는 원고를 “이미지까지 완성”이라고 부르지 않는다. 업로드 방식이 정해지기 전에는 본문과 이미지 파일·위치 안내를 묶어 준비하는 수준이다. 계정 자동 게시와는 별개의 범위다.

## 2. 주제만 줘도 AI가 맡을 일

`주제·사진·짧은 메모 → 자료 확인 → 장르·관점 결정 → 구성·집필 → 이미지·멘트 → 퇴고·검수 → 완성 글`

- 주제 외의 재료는 선택 사항이다. 독자·분량·말투·수익 링크 등은 기존 카테고리 설정과 이전 수정에서 기본값을 가져온다.
- 주제에 필요한 사실은 AI가 먼저 조사한다. 사용자가 핵심 답·출처·모든 소제목을 적어야 생성되는 구조로 만들지 않는다.
- 실제 경험이 있어야 성립하는 주제에서 경험이 없으면, 가능한 자료 기반 형식으로 먼저 제안·제작한다. 방문기처럼 꾸미지 않는다.
- 결과 화면은 완성 글이 중심이다. 과정 분석은 필요할 때만 펼쳐 본다.
- “좀 더 담백하게”, “이 부분은 소개보다 내 생각으로”, “사진 3번 뒤를 줄여”처럼 짧은 수정으로 다시 완성한다.

## 3. 장르는 6개, 변형은 재료에 맞춰 선택

### A. 일상·브이로그·이야기

**재료:** 실제 사진·행동 메모·시간·장소·생각 중 있는 것. 긴 일기를 먼저 작성할 필요는 없다.

**기본 흐름:** 작은 장면 → 그날의 기대·선택 → 예상과 다른 지점 → 다음 행동 → 남는 장면.

**변형:** 시간 순서 / 한 장면을 확대 / 결과를 먼저 보여 준 뒤 과정 / 이전 일상과 이번 변화.

- AI는 사건을 줄줄이 나열하지 않고 독자가 따라갈 줄기 하나를 잡는다.
- 사진 사이에는 행동·전환을 넣고, 감정은 사진과 실제 메모에 맞춘다. 모든 사진을 길게 설명하지 않는다.
- 멘트는 짧은 속마음·소소한 발견·이전 장면과의 차이를 맡는다.
- 이모티콘은 꼭 필요한 반응에 선택적으로 붙인다. 담백한 일상은 없이도 가능하다.
- 마지막은 교훈을 강제로 만들지 않고 그날의 작은 변화나 장면으로 닫는다.
- 연구 연결: E3의 계획과 현실, V2의 장면·속마음, F2의 일상 마무리.

**재료가 없을 때:** “최근 다녀왔다” 같은 경험담 대신 일상 관찰·계절 고찰·실험 제안 등으로 바꾼다. 사용자가 실제로 했다고 확인하지 않은 행동은 쓰지 않는다.

### B. 맛집·카페·공간 소개

**재료:** 장소의 확인 가능한 정보. 실제 방문 메모·사진이 있으면 후기 요소를 함께 사용.

**기본 흐름:** 방문 목적·선택 이유 → 공간의 핵심 특징 → 메뉴·이용 경험 또는 확인 정보 → 조건·아쉬움 → 맞는 사람.

**변형:** 혼밥·작업·대화 등 목적 중심 / 동선 따라가기 / 메뉴 하나를 깊게 / 후보 두 곳의 조건 비교.

- 첫머리에서 “어떤 목적으로 갈 만한 곳인가”를 잡는다. 모든 항목을 똑같은 분량으로 다루지 않는다.
- 가격·영업시간·휴무·예약·좌석·주차는 최신 근거가 있을 때만 확정한다. 취향 판단과 장소 정보를 섞지 않는다.
- 방문 자료가 있으면 “맛있었다”보다 온도·식감·양·소음·앉는 방식처럼 관찰 가능한 차이를 중심에 둔다.
- 사진은 외관·입구 → 자리·분위기 → 메뉴·음식 → 특징 디테일로 이어질 수 있다. 주제에 필요 없는 종류는 생략한다.
- 캡션은 “카페 내부” 같은 이름만 반복하기보다 독자가 볼 지점을 알려 준다. 실제 관찰이 없는 감각은 덧붙이지 않는다.
- 조용함이 장점이어도 대화·회전율에는 다른 조건이 생길 수 있다. 누구에게 맞고 안 맞는지 결론을 낸다.
- 연구 연결: F1의 취향과 이유, F2의 과정·주의, F3의 조건별 다른 선택.

**재료가 없을 때:** 공식 정보·메뉴·정책을 기반으로 소개하거나 지역·이용 목적의 비교 글을 쓴다. 생성한 음식 사진·가짜 매장 사진을 실제 방문 증거로 쓰지 않는다.

### C. 제품·도구·콘텐츠 소개와 비교

**재료:** 제품 사양·제공 기능·가격 조건·사용 목적. 사용·시청 메모가 있으면 실제 평가를 포함.

**기본 흐름:** 독자가 고르는 이유 → 선택 기준 → 중요한 차이 → 조건별 선택 → 안 사도 되는 경우.

**변형:** 두 선택지만 비교 / 한 제품의 사용 목적 / 입문용과 오래 쓸 선택 / 이미 가진 것으로 충분한 경우.

- 비교표는 결정에 영향을 주는 항목만 남긴다. 제공 정보가 없는데 칸을 채우려고 숫자를 만들지 않는다.
- “가성비 최고”보다 가격과 필요한 기능의 관계를 설명한다. 제휴 링크를 넣기 위해 결론을 바꾸지 않는다.
- 이미지는 전체 모습·중요 기능·차이 비교·실제 사용 장면 중 필요한 것. 공식 이미지의 사용 조건도 확인한다.
- 마무리는 독자 유형마다 이유가 있는 선택을 준다. 아무 판단 없이 둘 다 좋다고 끝내지 않는다.
- 연구 연결: E4의 조건별 비교, F3의 다른 선택, F1의 취향 근거.

### D. 설명·해설

**재료:** 실제 질문, 원리와 확인 가능한 근거, 독자가 헷갈리는 지점.

**기본 흐름:** 익숙한 의문·모순 → 짧은 답 → 사례·비유 → 원리 → 예외·적용.

**변형:** 오해 하나를 풀기 / 과정 따라가기 / 두 상황 비교 / 독자가 먼저 결과를 예상하게 하기.

- 어려운 말보다 사례를 먼저 보여 줄 수 있다. 비유의 범위를 넘어가는 부분은 구분한다.
- 정보는 독자가 이해할 순서로 준다. 설명이 필요한 부분은 짧게 줄이는 것보다 정확한 연결이 우선이다.
- 이미지는 단계 그림·비교 도식·간단한 그래프가 맡는다. 본문의 내용을 다시 전부 적은 카드뉴스는 피한다.
- 감탄·농담·이모티콘은 내용 이해에 도움이 있을 때만 사용한다.
- 마무리에는 처음의 질문에 이제 어떻게 답할 수 있는지 남긴다.
- 연구 연결: F5의 통념과 원리, V1의 단계적 반전, E1의 기억할 수 있는 비유.

### E. 고찰·에세이·취향

**재료:** 구체적인 관찰·문제, 여러 설명·의견, 사용자의 알려진 선호와 판단.

**기본 흐름:** 신경 쓰인 현상 → 처음 생각 → 다른 설명·반례 → 생각이 달라진 이유 → 지금의 입장.

**변형:** 질문 하나를 끝까지 / 찬반 대신 조건 나누기 / 일상에서 넓은 주제로 / 넓은 주제에서 작은 선택으로.

- 인터넷 글을 요약해 늘어놓는 것으로 끝내지 않는다. 해석의 기준과 결론을 새로 만든다.
- 반대 설명을 일부러 약하게 만들어 이기지 않는다. 실제로 중요한 반례를 다룬다.
- “나”라는 말만 넣는다고 개인적인 글이 되지 않는다. 사용자가 말하지 않은 신념·사적인 사연은 대신 정하지 않는다.
- 그림은 생각을 보여 주는 간단한 도식이나 맥락에 맞는 분위기 이미지로 선택한다. 글의 판단을 사진이 가리지 않게 한다.
- 이모티콘을 쓰지 않는 문체도 허용한다. 과한 명언·인생 교훈은 줄인다.
- 연구 연결: E2의 관점 전환, E5의 가설·반례, V3의 독자적인 분류.

### F. 후기·평가·피드백

**재료:** 실제 사용·방문·시청 기록, 기대, 비교 기준, 달라진 점. 자료만 있으면 조사 평가라고 명시.

**기본 흐름:** 기대와 조건 → 관찰·결과 → 좋은 점의 이유 → 아쉬운 점의 영향 → 다시 선택할지·맞는 사람.

**변형:** 첫인상과 일정 기간 후 / 기대와 실제 / 이전 것과 비교 / 불편 한 가지를 중심으로.

- 점수·장점 개수를 먼저 정하지 않는다. 실제로 중요한 차이에 분량을 배정한다.
- 사용 기간·방문 시간 같은 조건이 평가에 영향을 주면 남긴다. 의미 없는 세부 사항까지 늘리지 않는다.
- 좋은 점과 아쉬운 점을 의무적으로 같은 수로 맞추지 않는다. 각각 판단에 어떤 영향을 주는지 설명한다.
- 사진·기록·전후 비교가 주장과 연결돼야 한다. 확인되지 않은 소비자 반응은 만들지 않는다.
- 실제 수정·성과·비용이 있는 AI 작업기는 생성 시연보다 “내 수정이 얼마나 남았나”를 중요한 평가로 삼을 수 있다.
- 연구 연결: F3·F4의 사용 디테일과 독자 피드백, K1의 책과 실제 경험 연결.

## 4. 이미지·멘트는 함께 설계한다

| 역할 | 배치할 지점 | 붙일 멘트 |
|---|---|---|
| 분위기·장면 | 도입 또는 장면이 바뀌는 곳 | 글의 시작점이 되는 관찰 한 줄 |
| 증거·디테일 | 판단의 이유 바로 옆 | 그 사진에서 실제로 확인할 부분 |
| 과정 | 다음 단계로 넘어가는 곳 | 앞뒤의 변화·헷갈릴 조건 |
| 비교 | 선택 기준을 설명하는 곳 | 무엇이 달라지고 누구에게 중요한지 |
| 설명 도식 | 추상적인 원리를 풀어야 하는 곳 | 그림이 말하는 관계·범위 |
| 여운·전환 | 이야기가 닫히거나 바뀌는 곳 | 과한 요약 없이 남는 한 문장 |

이미지마다 `역할 / 본문 위치 / 사용할 파일·URL / 준비 상태 / 캡션 / 대체텍스트 / 출처·사용 범위`를 제작 데이터로 남긴다. 독자는 필요한 본문·캡션만 읽는다.

- 이미지 수와 문단 간격을 모든 장르에 고정하지 않는다. 없으면 글이 이해되지 않는 사진부터 준비한다.
- 실제 기록은 사용자 사진을 우선한다. 자료 사진은 권한을 확인한다. 개념 설명·추상 분위기는 직접 만든 그림·도식으로 처리할 수 있다.
- 확보할 수 없는 사진 때문에 글 전체가 빈칸이 되지 않게 한다. 사실성을 유지하는 다른 장르·도식으로 완성 가능한지 AI가 판단한다.
- 생성 이미지 도구 연결은 후속 구현 대상이다. 지금의 도우미가 이미지 제작·수집·티스토리 업로드까지 처리하는 것은 아니다.

## 5. 말투·문단·이모티콘 제작 규칙

카테고리별로 존댓말·반말, 친근함, 감탄·농담·이모티콘의 강도, 평가 기준을 유지한다. 특정 필자의 문구·캐릭터·상징을 반복해서 베끼는 방식은 사용하지 않는다.

- 자연스러움은 모호한 감탄보다 구체적인 선택과 관찰에서 만든다.
- 짧은 반응 문장과 필요한 설명 문장을 섞는다. 일부러 모든 문장을 짧게 자르거나 줄마다 줄바꿈하지 않는다.
- 원고마다 동일한 인사·소제목·마무리가 반복되는지 지난 글과 비교한다.
- 반문·농담·이모티콘은 없어도 된다. 주제의 무게와 사용자의 선호에 맞춘다.
- 사진 멘트는 본문 복제보다 시선·반응·연결을 맡는다.
- 사용자가 고친 표현을 다음 원고에 반영하되, 한 글에서의 상황적인 수정을 모든 카테고리에 적용하지 않는다.

## 6. 자동 검수와 성과 기준

**글의 검수:** 제목의 약속을 본문이 지키는가 / 중심 관점이 있는가 / 앞뒤의 흐름이 맞는가 / 확인된 사실과 경험에 근거하는가 / 반복 문구·과장·군더더기가 남았는가.

**이미지의 검수:** 실제 준비돼 있는가 / 본문 판단과 맞는가 / 사용 가능한가 / 사실 기록처럼 오해할 요소가 없는가 / 캡션·대체텍스트가 맞는가.

**게시 준비:** 이미지·출처·표시의 부족을 숨기지 않고 짧게 보여 준다. 실제 게시 허용·계정 연결이 확인되기 전에는 원고 생성과 자동 등록을 같은 기능으로 설명하지 않는다.

평가의 첫 기준은 사용자에게 얼마나 적게 손질이 남는지다. 개발 후 실제 원고로 다음을 측정한다.

| 항목 | 기록할 것 |
|---|---|
| 수정 부담 | 최종 손질에 걸린 시간, 수정한 주요 문단·제목·캡션 |
| 내용 품질 | 사실 오류, 불필요한 확인 질문, 원고에서 제거한 군더더기 |
| 이미지 품질 | 없는 이미지·맞지 않는 캡션·권한 미확인 자산이 남았는지 |
| 반복성 | 최근 글과 도입·표현·구성·주제가 지나치게 겹치는지 |
| 실제 반응 | 게시 후 확인 가능한 읽기·반응·질문. 조회만으로 양질이라고 단정하지 않음 |

“손질 5분 안팎” 같은 수치는 향후 시험 목표로 둘 수 있으나 아직 검증된 성능이 아니다. 매일 자동으로 많은 글을 만드는 것보다 게시할 만한 완성 글을 안정적으로 준비하는 것이 먼저다.

## 7. 후속 개발의 메뉴·기능 방향

`블로그·카페 → 포스팅 자동화 → 오늘의 주제 / 완성 글 / 장르·말투`

- 기본 화면: 주제 선택·직접 입력 → 완성 글 확인 → 짧은 수정 → 게시용 복사·이미지 묶음.
- 세부 설정은 필요할 때 여는 장르·카테고리 아래에 둔다. 사용 시작에 긴 설정 문답을 요구하지 않는다.
- 기존 저장·복구·이력·HTML 복사·콘텐츠 연결은 재사용한다.
- 빈칸 생성 중심의 현재 템플릿, 수동 기획 중심 화면, 선택적 짧은 초안 호출은 완성 원고 제작 중심으로 개편할 대상이다.
- API로 매일 자동 생성할 실행 수단과 이 대화에서 직접 집필해 전달하는 방식은 구분한다. 실제 모델 연결·비용·이미지 수단·저장 흐름은 후속 구현에서 검증한다.

이번에는 요구·분석·설계를 문서화했다. 화면·모델·생성 로직을 개편한 것으로 기록하지 않는다.
