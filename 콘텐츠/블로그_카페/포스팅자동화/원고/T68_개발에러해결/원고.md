# npm.ps1 cannot be loaded because running scripts is disabled on this system — 윈도우 PowerShell 해결법 (2026)

<!-- 제휴가 있으면 이 줄에 대가성 문구 -->

PowerShell 에서 `npm install` 을 쳤더니 이렇게 나온다.

```
npm : File C:\Program Files\nodejs\npm.ps1 cannot be loaded because running scripts is disabled on this system.
    + FullyQualifiedErrorId : UnauthorizedAccess
```

결론부터 말한다. **Node 가 고장 난 게 아니라 PowerShell 의 실행 정책이 `.ps1` 파일을 막은 것이다.** 해결은 한 줄이고, 이 줄을 `Unrestricted` 로 치는 글이 많지만 그럴 필요가 없다.

```powershell
Set-ExecutionPolicy -ExecutionPolicy RemoteSigned -Scope CurrentUser
```

관리자 권한이 필요 없고, 내 계정에만 적용되고, 로컬 스크립트만 풀어 준다. 이 글은 왜 이게 정답에 가까운지, 안 풀릴 때 어디를 봐야 하는지를 윈도우 11 기준으로 정리한다.

## 왜 cmd 에서는 되고 PowerShell 에서만 막히나?

Node.js 를 설치하면 `npm` 을 실행하는 파일이 `npm.cmd` 와 `npm.ps1` 두 개 깔린다. PowerShell 에서 `npm` 이라고만 치면 `.ps1` 쪽이 불려 가는 경우가 많고, 정책이 스크립트를 막고 있으면 이 에러가 난다. cmd 는 실행 정책이 없는 셸이라 같은 명령이 그대로 돈다. (파일 두 개가 깔린다는 설명은 커뮤니티 글 기준이고, 내 PC 는 아래 명령으로 직접 확인한다.)

```powershell
Get-Command npm -All
```

공식 문서가 정의한 `Restricted` 정책은 "개별 명령은 허용하지만 스크립트는 허용하지 않는" 상태다. `.ps1` 스크립트, `.psm1` 모듈, 프로필 파일이 전부 막힌다. 모든 범위의 정책이 비어 있을 때(`Undefined`) Windows 클라이언트의 유효 정책이 바로 이 `Restricted` 다. 새로 설치한 윈도우 PC 에서 이 에러를 자주 만나는 이유다.

## 내 PC 는 지금 어떤 상태인가: 범위별로 읽는다

먼저 현재 상태를 본다.

```powershell
Get-ExecutionPolicy -List
```

출력은 이런 모양이다.

| Scope | ExecutionPolicy | 뜻 |
|---|---|---|
| MachinePolicy | Undefined | 그룹 정책(컴퓨터). 값이 있으면 아래를 전부 이긴다 |
| UserPolicy | Undefined | 그룹 정책(사용자) |
| Process | Undefined | 지금 창에서만 유효 |
| CurrentUser | Undefined | 내 계정 |
| LocalMachine | Undefined | PC 전체 (관리자 필요) |

읽는 법은 위에서 아래로, 처음으로 `Undefined` 가 아닌 값이 유효 정책이다. 그룹 정책이 없다면 우선순위는 `Process` > `CurrentUser` > `LocalMachine` 이다. 전부 `Undefined` 면 유효 정책은 `Restricted` 이므로 막히는 게 정상이다. 한 줄로 확인하려면 이렇게 친다.

```powershell
Get-ExecutionPolicy
```

## 어떻게 푸나: 범위를 좁게, 정책을 약하게 말고 적당하게

정책 이름별로 무엇이 풀리는지부터 본다. (확인일 2026-10-20, PowerShell 7.6 문서 기준)

| 정책 | 로컬 스크립트 | 인터넷에서 받은 스크립트 | 비고 |
|---|---|---|---|
| Restricted | 막힘 | 막힘 | 명령 한 줄씩만 가능 |
| AllSigned | 서명 필요 | 서명 필요 | 내가 짠 스크립트도 서명해야 함 |
| RemoteSigned | 실행 | 서명 필요 (Unblock-File 로 풀면 실행) | 윈도우 서버의 기본값 |
| Unrestricted | 실행 | 경고 후 실행 | 약함 |
| Bypass | 실행 | 실행 | 경고도 없음 |

개발 PC 에서 필요한 건 "내가 만든 스크립트와 npm 래퍼가 돈다" 뿐이다. 그래서 고르는 기준은 두 가지다. 범위는 좁을수록, 정책은 필요한 만큼만 푼다.

### 사람 유형별 선택

| 상황 | 추천 | 명령 |
|---|---|---|
| 내 개인 PC, 계속 개발한다 | CurrentUser + RemoteSigned | `Set-ExecutionPolicy -ExecutionPolicy RemoteSigned -Scope CurrentUser` |
| 이번 한 번만 돌리면 된다 | Process + Bypass | `Set-ExecutionPolicy -ExecutionPolicy Bypass -Scope Process` |
| npm 한 번이면 된다 | 정책을 안 건드리고 `.cmd` 로 | `npm.cmd install` |
| PC 를 여러 명이 쓴다 | LocalMachine (관리자 PowerShell) | `Set-ExecutionPolicy -ExecutionPolicy RemoteSigned -Scope LocalMachine` |

`Process` 범위는 디스크에 저장되지 않는다. 값은 `$Env:PSExecutionPolicyPreference` 에 담겼다가 창을 닫으면 사라진다. 임시로 푸는 데 알맞다.

실행하면 확인 질문이 나올 수 있다. `Y` 를 누르고, 바로 검증한다.

```powershell
Get-ExecutionPolicy -List
npm -v
```

`CurrentUser` 줄이 `RemoteSigned` 로 바뀌고 버전 번호가 나오면 끝이다. 정책 변경은 즉시 적용되어 PowerShell 을 다시 켤 필요가 없다.

## 풀었는데도 안 될 때 확인할 세 가지

1. **MachinePolicy·UserPolicy 에 값이 있다.** 그룹 정책이 정한 값이라 `Set-ExecutionPolicy` 로 못 바꾼다. 회사 PC 라면 IT 부서 몫이다. 이때는 `npm.cmd` 로 우회하거나 cmd 에서 실행하는 쪽이 현실적이다.
2. **더 높은 범위가 덮고 있다.** `LocalMachine` 을 바꿨는데 `CurrentUser` 가 `Restricted` 면 `CurrentUser` 가 이긴다. 공식 문서도 명령은 성공하는데 유효 정책이 안 바뀔 수 있다고 적는다. `-List` 로 범위를 전부 본다.
3. **다른 PowerShell 을 쓰고 있다.** Windows PowerShell(5.1)과 PowerShell 7(`pwsh`)은 각각 열어서 `Get-ExecutionPolicy -List` 를 따로 확인한다. VS Code 통합 터미널이 둘 중 어느 쪽인지도 같이 본다.

## 인터넷에서 받은 .ps1 이 막힐 때

`RemoteSigned` 로 풀어도, 브라우저로 내려받은 스크립트는 "인터넷에서 왔다" 표시가 붙어 막힌다. 이 표시는 파일 단위로 풀 수 있다.

```powershell
Unblock-File -Path .\setup.ps1
```

출처를 읽어 본 스크립트에만 쓴다. 참고로 `curl.exe`, `Invoke-WebRequest` 로 받은 파일에는 이 표시가 안 붙을 수 있다고 공식 문서가 적는다. 같은 정책인데 받은 방법에 따라 막히기도, 안 막히기도 하는 이유다.

## 되돌리기

원래 상태(정책 없음)로 돌리려면 `Undefined` 로 지정한다.

```powershell
Set-ExecutionPolicy -ExecutionPolicy Undefined -Scope CurrentUser
```

모든 범위가 비면 다시 `Restricted` 로 돌아간다.

## 이 방법이 맞지 않는 경우

실행 정책은 공식 문서의 표현대로 **보안 경계가 아니라 심층 방어**다. 스크립트 내용을 명령줄에 그대로 붙여 넣으면 정책과 무관하게 돈다. 그래서 정책을 풀어도 큰 구멍이 생기는 것도, 강하게 둔다고 악성코드가 막히는 것도 아니다. 출처 모를 스크립트를 실행하지 않는 습관이 정책보다 훨씬 중요하다. 그리고 이 설정은 PowerShell 에서 스크립트를 실행하는 문제만 푼다. `npm install` 이 이후에 내는 다른 에러(권한, 네트워크)는 별개다.

## 다음부터 이렇게

- 에러 메시지에 `.ps1` 과 `running scripts is disabled` 가 보이면 코드를 의심하지 말고 `Get-ExecutionPolicy -List` 부터 친다.
- 개인 PC 는 `CurrentUser` + `RemoteSigned` 한 번이면 계속 쓴다. `Unrestricted` 는 올리지 않는다.
- 급하면 `npm.cmd` 로 부르고, 정책은 나중에 푼다.

지금 막혀 있다면 PowerShell 에서 `Get-ExecutionPolicy -List` 한 줄만 먼저 쳐 보자.
