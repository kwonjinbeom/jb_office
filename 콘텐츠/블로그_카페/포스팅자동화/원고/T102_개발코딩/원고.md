# Error [ERR_MODULE_NOT_FOUND]: Cannot find module 해결 (Node.js 22, 윈도우 11)

<!-- 제휴가 있으면 이 줄에 대가성 문구 -->

> ERR_MODULE_NOT_FOUND 는 원인이 셋이다. 메시지에 Cannot find module 과 경로가 보이면 import 경로에 .js 를 붙이고, Cannot find package 가 보이면 npm install 을 한다. 확인은 Node v22.17.0, 윈도우 11 에서 했다.

## 메시지 한 줄로 원인 가르기

`package.json` 에 `"type": "module"` 이 있는 프로젝트에서 같은 에러 이름이 세 가지 모습으로 나온다.

| 메시지 | 원인 | 해결 |
|---|---|---|
| `Cannot find module '...\utils\helper' imported from ...` | 상대 경로 import 에서 확장자 생략 | `.js` 를 붙인다 |
| `Directory import '...\dirmod' is not supported` (에러 코드는 ERR_UNSUPPORTED_DIR_IMPORT) | 폴더 경로만 import | `./dirmod/index.js` 로 쓴다 |
| `Cannot find package 'lodash' imported from ...` | 패키지 미설치 | `npm install lodash` |

## 확장자를 빼먹은 경우

재현 구성은 이렇다.

```
t102/
  package.json      {"type":"module"}
  a.js
  utils/helper.js
```

```js
// a.js
import { hello } from "./utils/helper";
console.log(hello());
```

`node a.js` 를 실행하면 아래가 나온다 (앞 경로는 줄였다).

```
Error [ERR_MODULE_NOT_FOUND]: Cannot find module 'C:\...\t102\utils\helper' imported from C:\...\t102\a.js
Did you mean to import "./utils/helper.js"?
```

ESM 에서 상대 경로는 확장자까지 써야 한다. CommonJS 의 `require` 처럼 `.js` 를 알아서 붙여 주지 않는다. 메시지의 `Did you mean` 줄이 그대로 정답이다.

```js
import { hello } from "./utils/helper.js";
```

## 폴더만 import 한 경우

```js
import x from "./dirmod";   // dirmod/index.js 가 있어도
```

```
Error [ERR_UNSUPPORTED_DIR_IMPORT]: Directory import '...\dirmod' is not supported resolving ES modules imported from ...\b.js
Did you mean to import "./dirmod/index.js"?
```

폴더의 `index.js` 를 자동으로 찾는 동작도 ESM 에는 없다. `./dirmod/index.js` 로 풀어 쓴다.

## 패키지가 없는 경우

```js
import _ from "lodash";
```

```
Error [ERR_MODULE_NOT_FOUND]: Cannot find package 'lodash' imported from ...\c.js
```

경로가 아니라 package 라고 나오면 `node_modules` 에 없다는 뜻이다. `npm install lodash` 후 다시 실행한다. 설치했는데도 나면 `node` 를 실행하는 폴더와 `package.json` 이 있는 폴더가 같은지 본다.

## 윈도우에서 조심할 것

`./utils/Helper.js` 처럼 대소문자를 틀리게 써도 이 PC 에서는 그대로 실행됐다. 윈도우 파일 시스템이 대소문자를 구분하지 않아서다. 리눅스 서버나 CI 에서는 같은 코드가 경로를 못 찾을 수 있으니 파일명 그대로 쓰는 편이 안전하다.

확장자를 매번 쓰기 싫은 프로젝트는 번들러나 TypeScript 환경을 쓰는 쪽이 맞다. 순수 Node 로 실행하는 스크립트라면 확장자를 쓰는 게 규칙이다.
