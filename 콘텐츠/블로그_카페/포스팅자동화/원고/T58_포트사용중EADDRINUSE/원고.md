## 손질하면 좋아지는 곳 (사용자 몫)

1. 본인이 실제로 쓰는 포트(3000/5173/8080 등)로 예시 포트를 바꿔 한 번 돌려 보고, `netstat -ano | findstr :3000` 결과 캡처(사진 1)를 넣으면 체감이 크게 오른다.
2. 사용하는 프레임워크(Next.js·Vite·Express·NestJS)별로 포트를 바꾸는 실제 명령을 쓰는 스택에 맞춰 한 줄씩 교체하면 좋다.
3. nodemon·concurrently 같은 도구를 쓰는 환경이면, 그 도구에서 자식 프로세스가 안 죽어 포트가 남는 경우가 많으니 본인 경험 한 줄 덧붙이면 신뢰가 오른다.

# EADDRINUSE: address already in use :::3000 — 윈도우에서 포트 비우는 법 (2026)

<!-- 제휴가 있으면 이 줄에 대가성 문구 -->

`npm start` 나 `node server.js` 를 쳤는데 이 에러로 멈춘 적이 있을 것이다.

```
Error: listen EADDRINUSE: address already in use :::3000
    at Server.setupListenHandle [as _listen2] (node:net:...)
    at listenInCluster (node:net:...)
```

결론부터 말한다. **이건 코드 버그가 아니라, 3000번 포트를 이미 다른 프로세스가 잡고 있다는 뜻이다.** 보통은 아까 `Ctrl+C` 로 껐다고 생각한 서버가 실제로는 안 죽고 남아 있는 경우다. 해결은 포트를 바꾸는 게 아니라 **누가 그 포트를 잡고 있는지 찾아서 끝내는 것**이 정석이다. 리눅스는 `lsof` 로 끝나지만, 윈도우는 명령이 다르다. 이 글은 윈도우 기준으로 정리한다.

## 왜 나나: 포트는 한 프로세스만 쓴다

TCP 포트 하나는 동시에 한 프로세스만 수신(listen)할 수 있다. 서버가 `3000` 에서 듣고 있는데 또 다른 프로세스가 같은 `3000` 에 바인딩을 시도하면 OS가 거부하고, Node는 이를 `EADDRINUSE` 시스템 에러로 올린다. 공식 문서도 `EADDRINUSE (Address already in use)` 를 "이미 사용 중인 포트/주소에 바인딩하려 할 때 나는 에러" 로 정의한다.

흔한 원인은 세 가지다.

- **안 죽은 이전 서버**: 터미널을 닫거나 IDE를 강제로 껐을 때, `nodemon`·`concurrently` 가 띄운 자식 프로세스가 부모만 죽고 남아 포트를 계속 쥐고 있다. 가장 흔하다.
- **진짜 다른 앱**: 다른 프로젝트 서버, 혹은 포트를 쓰는 다른 프로그램(예: 일부 개발 도구)이 먼저 올라와 있다.
- **방금 종료 직후**: 막 끈 직후 잠깐은 소켓이 `TIME_WAIT` 상태로 남아 재바인딩이 거절될 수 있다. 몇 초 기다리면 풀린다. (OS별 대기 시간의 정확한 기본값은 확인 못 했다.)

참고로 포트 번호를 `80` 이나 `443` 처럼 1024 미만으로 바꿨을 때 나는 건 보통 EADDRINUSE가 아니라 `EACCES (Permission denied)` 다. 이건 "그 포트는 권한이 있어야 쓴다" 는 뜻이라 원인이 다르다. 에러 코드부터 구분하자.

## 1단계: 누가 포트를 잡고 있나 (윈도우)

윈도우에서 포트의 주인을 찾는 명령은 cmd와 PowerShell이 다르다. 둘 다 적는다.

### cmd: netstat 로 PID 찾기

```bat
netstat -ano | findstr :3000
```

옵션 의미는 공식 문서 그대로다. `-a` 는 모든 연결과 수신 포트, `-n` 은 주소·포트를 숫자로(이름 변환 안 함), `-o` 는 연결마다 **PID** 를 같이 보여 준다. 결과의 맨 오른쪽 숫자가 PID다.

```
  TCP    0.0.0.0:3000    0.0.0.0:0    LISTENING    18948
  TCP    [::]:3000       [::]:0       LISTENING    18948
```

여기서 PID는 `18948`. `LISTENING` 상태인 줄이 포트를 잡고 있는 녀석이다. 실행 파일 이름까지 보고 싶으면 `-b` 를 붙이면 되지만, 관리자 권한이 필요하고 느리다.

```bat
netstat -anob | findstr :3000
```

### PowerShell: Get-NetTCPConnection 로 찾기

PowerShell이면 더 깔끔하다. `-LocalPort` 로 포트를 바로 거르고, 소유 프로세스 PID는 `OwningProcess` 속성에 들어 있다.

```powershell
Get-NetTCPConnection -LocalPort 3000 -State Listen
# PID 로 어떤 프로그램인지까지 보기
Get-Process -Id (Get-NetTCPConnection -LocalPort 3000 -State Listen).OwningProcess
```

## 2단계: 그 프로세스를 끝낸다

PID를 알았으면 끝낸다.

### cmd: taskkill

```bat
taskkill /PID 18948 /F
```

`/F` 는 강제 종료다. nodemon 처럼 자식 프로세스를 거느린 경우엔 `/T` 를 더해 자식까지 함께 정리한다(공식 문서: "지정한 프로세스와 그것이 시작한 자식 프로세스를 종료").

```bat
taskkill /PID 18948 /T /F
```

### PowerShell: 한 줄로

PowerShell은 찾기와 끝내기를 이어서 쓸 수 있다.

```powershell
Stop-Process -Id (Get-NetTCPConnection -LocalPort 3000 -State Listen).OwningProcess -Force
```

끝낸 뒤 `netstat -ano | findstr :3000` 을 다시 쳐서 **아무것도 안 나오면** 포트가 비었다는 뜻이다. 이제 서버를 다시 올리면 된다.

## 3단계(대안): 포트를 아예 바꾼다

"저 프로세스는 꼭 켜져 있어야 한다" 면 내 서버 포트를 바꾸는 게 맞다. 프레임워크별로 다르다.

```bat
:: 범용: 많은 Node 서버가 PORT 환경변수를 읽는다
set PORT=3001 && npm start
```

```powershell
# PowerShell 은 set 문법이 다르다
$env:PORT=3001; npm start
```

- **Next.js**: `next dev -p 3001`
- **Vite**: `vite --port 5174` (또는 `vite.config` 의 `server.port`)
- **직접 만든 Express/NestJS**: 코드에서 `app.listen(process.env.PORT || 3000)` 처럼 환경변수를 먼저 읽게 짜 두면 매번 코드를 안 고쳐도 된다.

## 4단계: 코드에서 우아하게 처리하기 (직접 만든 서버)

서버를 직접 작성한다면, EADDRINUSE가 났을 때 프로세스가 스택 트레이스를 토하며 죽는 대신 안내하거나 재시도하게 할 수 있다. Node 공식 문서가 `net.Server` 의 `'error'` 이벤트 예제로 **그대로 보여 주는 패턴**이다.

```js
const net = require('node:net');
const PORT = 3000;
const HOST = '0.0.0.0';
const server = net.createServer();

server.on('error', (e) => {
  if (e.code === 'EADDRINUSE') {
    console.error('Address in use, retrying...');
    setTimeout(() => {
      server.close();
      server.listen(PORT, HOST);
    }, 1000);
  }
});

server.listen(PORT, HOST);
```

핵심은 `e.code === 'EADDRINUSE'` 로 다른 에러와 구분하는 것이다. 그리고 공식 문서가 짚듯, `net.Server` 는 `'error'` 가 떠도 `server.close()` 를 직접 부르지 않으면 `'close'` 이벤트가 자동으로 뒤따르지 않는다. 그래서 위 예제도 재시도 전에 `server.close()` 를 명시적으로 부른다. 실무에선 무한 재시도 대신 "같은 포트가 계속 막혀 있으면 안내 후 종료" 로 두는 편이 낫다.

## 다음부터 이렇게

| 상황 | 할 일 |
|---|---|
| 에러 코드가 EADDRINUSE | 포트를 바꾸기 전에 누가 잡았는지부터 찾는다 |
| 포트 주인 찾기 (cmd) | `netstat -ano \| findstr :3000` → 맨 오른쪽 PID |
| 포트 주인 찾기 (PowerShell) | `Get-NetTCPConnection -LocalPort 3000 -State Listen` |
| 끝내기 | `taskkill /PID <PID> /F` (자식까지면 `/T` 추가) |
| 꼭 켜둬야 하는 프로세스 | 내 서버 포트를 `PORT`·`-p` 로 바꾼다 |
| 에러 코드가 EACCES | 1024 미만 포트 권한 문제 — 원인이 다르다 |

가장 자주 겪는 건 "안 죽은 이전 dev 서버" 다. 평소에 서버를 올릴 때 `app.listen(process.env.PORT || 3000)` 로 환경변수를 먼저 읽게 짜 두고, 포트가 막히면 `netstat -ano | findstr :포트` 한 줄로 PID를 찾는 습관만 들여도 이 에러는 1분 안에 끝난다.
