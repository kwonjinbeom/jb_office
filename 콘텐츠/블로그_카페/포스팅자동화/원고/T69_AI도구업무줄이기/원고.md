# Claude Haiku 5.5 반복 업무에 붙이면 1,000건에 얼마? (요약·분류 비용 계산)

<!-- 제휴가 있으면 이 줄에 대가성 문구 -->

결론부터 적는다. 입력 3,000토큰짜리 문서 1,000건을 요약해 300토큰씩 받는 일은 Claude Haiku 5.5 로 약 $0.45, Haiku 4.5 로 약 $4.5, Sonnet 5.5 로 약 $9 다. 반복 업무 비용 때문에 AI 붙이기를 미뤘다면 이 숫자가 기준이 된다. 단 아래 조건이 하나라도 걸리면 계산이 달라진다.

## Claude Haiku 5.5 는 무엇이 바뀌었나?

2026년 10월 7일 Anthropic 이 발표한 소형 모델이다. 모델 ID 는 `claude-haiku-5-5` 이고, 발표문은 "가장 빠르고 싸고, 소형 중 가장 유능한 모델" 이라고 소개한다. 눈여겨볼 점은 둘이다.

- 가격이 입력 $1 → $0.10, 출력 $5 → $0.50 으로 내려갔다 (100만 토큰 기준, 프롬프트 100k 토큰 이하).
- Haiku 급으로는 처음으로 effort(Low, Med, High, Xhigh, Max) 를 고를 수 있다. 쉬운 일은 낮게, 헷갈리는 일은 높게 쓰면 된다.

발표문이 권하는 용도는 요약, 컴팩션(긴 대화 줄이기), DB 쿼리, 분류, 빠른 조회, 그리고 큰 모델 옆의 서브에이전트다.

## 내 반복 업무에 맡기면 1,000건에 얼마인가?

가정은 한 건당 입력 3,000토큰(A4 한 장 반 정도), 출력 300토큰이다. 가격은 확인일(10월 20일) 기준이다.

| 모델 | 입력 단가 | 출력 단가 | 1건 | 1,000건 |
|---|---|---|---|---|
| Haiku 5.5 | $0.10 | $0.50 | $0.00045 | 약 $0.45 |
| Haiku 4.5 | $1 | $5 | $0.0045 | 약 $4.5 |
| Sonnet 5.5 | $2 | $10 | $0.009 | 약 $9 |

계산식은 `(입력토큰 × 입력단가 + 출력토큰 × 출력단가) ÷ 1,000,000` 이다. Haiku 5.5 는 3,000 × 0.10 = 0.0003, 300 × 0.50 = 0.00015, 합계 $0.00045 가 나온다.

내 상황에 맞추는 법은 간단하다.

- 하루 50건 메일 분류: 한 달(30일) 1,500건, 입력 1,000토큰·출력 50토큰이면 약 $0.19 다.
- 회의록 요약 하루 5건: 입력 10,000토큰·출력 500토큰이면 한 달 150건에 약 $0.19 다.
- 로그 정리처럼 한 번에 수십만 토큰을 넣는 일: 아래 함정에 걸린다.

## 광고의 "90% 인하" 와 실제 청구가 다른 이유는?

발표문 기준으로 "평균 75% 저렴" 이다. 100k 토큰 이하 프롬프트는 90%, 초과는 50% 저렴하다. 이유가 둘 있다.

1. 100k 토큰을 넘기면 단가가 입력 $0.50, 출력 $2.50 으로 5배가 된다. 긴 문서를 통째로 넣는 습관이 있으면 싼 모델의 이점이 줄어든다. 100k 아래로 쪼개 넣는 쪽이 싸다.
2. 새 토크나이저는 같은 텍스트도 토큰이 조금 더 나온다. 한글은 특히 내 데이터로 직접 재야 한다. 위 표의 3,000토큰은 가정이므로, 실제 usage 값으로 바꿔 계산하는 것이 맞다.

캐시를 쓰면 더 내려간다. 반복되는 지시문(시스템 프롬프트)은 캐시 읽기 단가가 100만 토큰당 $0.01(100k 이하)이다. 같은 지시문을 매 건 붙이는 분류 작업에 효과가 크다.

## 어디까지 맡기고, 어디서 큰 모델로 올리나?

고르는 기준은 세 가지다. 틀리면 얼마나 아픈가, 입력이 얼마나 긴가, 여러 단계를 스스로 이어 가야 하는가.

| 일 | 추천 | 이유 |
|---|---|---|
| 메일·티켓 분류, 태그 달기 | Haiku 5.5 (Low~Med) | 짧고 반복적, 발표문 권장 용도 |
| 문서·회의록 요약 | Haiku 5.5 (Med) | 100k 이하로 쪼개면 가장 쌈 |
| DB 쿼리 초안 | Haiku 5.5 (High) + 사람 확인 | 틀린 쿼리는 실행 전에 걸러야 함 |
| 여러 파일을 고치는 코딩 에이전트 | Sonnet 5.5 이상 | 발표문도 복잡한 에이전트 코딩은 큰 모델이 낫다고 명시 |
| 계약·재무처럼 틀리면 손해가 큰 판단 | 큰 모델 + 사람 검토 | 단가보다 오류 비용이 큼 |

숫자로 보면 차이가 분명하다. 발표문 벤치마크에서 Terminal-Bench 4.0 은 Haiku 5.5 가 39.2%, Sonnet 5.5 가 70.6% 다. 요약·분류에 충분하다는 것과 코딩 에이전트까지 대신한다는 것은 별개다.

사람 유형별로 정리한다.

- 개인 개발자, 자동화 스크립트 몇 개: Haiku 5.5 하나로 시작해도 월 몇 센트~몇 달러 수준이다.
- 팀에서 코딩 에이전트를 쓰는 경우: 메인은 Sonnet 5.5, 검색·요약 같은 곁가지만 Haiku 5.5 서브에이전트로 돌리는 구성이 발표문이 말하는 쓰임에 맞다.
- 이미 Haiku 4.5 를 쓰는 경우: 모델 ID 만 바꾸면 되지만, 토크나이저 차이로 토큰 수가 달라지니 마이그레이션 가이드를 보고 1주일 청구액을 비교한다.

## 직접 붙이려면 어디서부터?

모델 ID 를 `claude-haiku-5-5` 로 지정하면 된다. 먼저 해 볼 순서는 다음과 같다.

1. 반복 업무 하나를 고른다. 100건을 샘플로 뽑는다.
2. 응답의 usage(입력·출력 토큰) 로 평균을 구해 위 식에 넣는다.
3. Haiku 5.5 와 Sonnet 5.5 결과 10건을 나란히 비교한다. 차이가 체감되지 않으면 Haiku 로 간다.
4. effort 를 Low 부터 올려 가며 품질이 바뀌는 지점을 찾는다.

[그림] 반복 업무 → Haiku 5.5 (분류·요약) → 애매한 건만 Sonnet 5.5 로 올리는 2단 흐름도

## 이런 경우는 굳이 바꾸지 않아도 된다

- 하루 몇 건이라 현재 요금이 월 1달러 미만이면 모델을 바꾸는 시간이 더 비싸다.
- 지금 쓰는 모델의 결과를 사람이 손볼 일이 거의 없다면 그대로 둔다.
- 보안 점검처럼 공격 기법을 다루는 일은 Haiku 5.5 의 안전장치(사이버 분야는 Haiku 4.5 보다 엄격)에 막힐 수 있다. 필요하면 Anthropic 의 Cyber Verification Program 을 신청해야 한다.

내 일에서 가장 자주 반복하는 작업 하나를 골라 샘플 100건의 토큰 수부터 재 보는 것이 첫 행동이다. 그 숫자가 나오면 모델 선택은 표 한 장으로 끝난다.
