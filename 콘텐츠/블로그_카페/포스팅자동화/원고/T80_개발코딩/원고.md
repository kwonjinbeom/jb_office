# ReferenceError: require is not defined in ES module scope 해결 (Node.js 22, 윈도우 11)

<!-- 제휴가 있으면 이 줄에 대가성 문구 -->

> `package.json` 에 `"type": "module"` 이 있으면 `.js` 파일은 ESM 으로 읽혀서 `require`·`__dirname` 이 사라진다. 이름을 `.cjs` 로 바꾸거나, `import` 로 고치고 `__dirname` 은 `import.meta.dirname` 으로 바꾸면 된다. 환경은 윈도우 11, Node.js v22.17.0, npm 10.9.2 이다.

## 에러를 그대로 재현했다

빈 폴더에 `package.json` 과 `a.js` 를 만들었다. `type` 한 줄이 전부다.

```json
{ "name": "t", "version": "1.0.0", "type": "module" }
```

```js
// a.js
const fs = require('fs');
console.log(fs.existsSync('.'));
```

`node a.js` 결과다. 경로는 줄였다.

```
ReferenceError: require is not defined in ES module scope, you can use import instead
This file is being treated as an ES module because it has a '.js' file extension and '...\esm\package.json' contains "type": "module". To treat it as a CommonJS script, rename it to use the '.cjs' file extension.
```

메시지가 원인과 해결을 이미 말해 준다. `.js` 라는 확장자와 `"type": "module"` 때문에 ESM 으로 처리됐다는 뜻이다.

같은 이유로 `__dirname` 도 막힌다.

```
ReferenceError: __dirname is not defined in ES module scope
```

## 해결은 셋 중 하나였다

| 상황 | 방법 |
|---|---|
| 파일 하나만 CJS 로 두고 싶다 | 이름을 `.cjs` 로 바꾼다 |
| 프로젝트를 ESM 으로 통일한다 | `import` 로 바꾸고 `__dirname` 은 아래처럼 |
| ESM 안에서 CJS 패키지 한두 개만 `require` 해야 한다 | `createRequire` |

ESM 으로 통일할 때 쓴 코드다. 실행해서 `esm true` 가 찍혔다.

```js
import path from 'node:path';
import { fileURLToPath } from 'node:url';

const __dirname = path.dirname(fileURLToPath(import.meta.url));
console.log(path.basename(__dirname), import.meta.dirname === __dirname);
```

Node 22.17 에서는 `import.meta.dirname` 이 같은 값이라 한 줄로 줄어든다. 이전 버전에서도 되는지는 확인 못 했다. 쓰는 Node 가 낮으면 위 `fileURLToPath` 방식이 안전하다.

`require` 가 꼭 필요하면 이렇게 한다. `function` 이 찍혔다.

```js
import { createRequire } from 'node:module';
const require = createRequire(import.meta.url);
console.log(typeof require('fs').existsSync);
```

## 고치고 나면 다음 에러가 나온다

ESM 으로 바꾸면 상대 경로 import 에 확장자가 필요하다. `import { hi } from './lib'` 은 이렇게 실패했다.

```
Error [ERR_MODULE_NOT_FOUND]: Cannot find module '...\esm\lib' imported from '...\esm\f.js'
Did you mean to import "./lib.js"?
```

`'./lib.js'` 로 쓰면 된다. 메시지의 제안이 그대로 답이다.

## 반대 방향은 Node 22.17 에서 이미 된다

CJS 프로젝트(`type: commonjs`)에서 `.mjs` 를 `require` 해 봤다. 에러 없이 `hi` 가 찍혔다. 예전 글에서 보던 `ERR_REQUIRE_ESM` 은 이 버전에서 재현되지 않았다. 다만 Node 20 이하에서도 같은지는 이 PC 에 없어서 확인 못 함.

`type` 이 아예 없는 패키지의 `.js` 에 `import` 를 쓰면 실행은 되지만 경고가 붙는다.

```
[MODULE_TYPELESS_PACKAGE_JSON] Warning: Module type of file:///.../i.js is not specified and it doesn't parse as CommonJS.
To eliminate this warning, add "type": "module" to ...\package.json.
```

경고가 거슬리면 `type` 을 명시하면 사라진다.

## 다음에는

새 프로젝트는 처음부터 `"type": "module"` 로 시작하고 `__dirname` 은 `import.meta.dirname` 을 쓰려 한다. 옛 스크립트가 많은 폴더는 파일마다 `.cjs` 로 바꾸는 쪽이 덜 번거롭다. Node 20 이하에서의 동작은 다음에 환경을 구해 확인해 보겠다.
