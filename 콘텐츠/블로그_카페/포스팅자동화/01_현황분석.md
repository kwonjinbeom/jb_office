## 2. Codex 문서를 갈아엎은 이유

1. **"트렌드에 맞춘"이 빠졌다.** 사용자의 요구는 트렌드 신호에서 글감을 뽑아 글을 만드는 자동화 구조다. 문서에는 트렌드를 어떻게 매일 모으고 주제로 바꾸는지가 없다. 주제 36개도 "계절·가설" 표시뿐이고 실제 신호에 근거하지 않았다.
2. **표본이 우리 채널과 다르다.** 분석한 14편은 영문 레시피 블로그(RecipeTin Eats 등), Wait But Why, Paul Graham이다. 네이버 블로그·티스토리 글의 문법(사진 리듬, 해요체, 지도·정보 블록, 대가성 표기 위치)과 거리가 멀다.
3. **'구조'가 없다.** 데이터 흐름·실행 시점·쓸 수 있는 API·서버 제약·비용·게시 방법이 정해지지 않았다. 원칙 문장은 많고, 만들 수 있는 설계는 적다.
4. **제약을 몰랐다.** 티스토리 Open API 종료(2024-02), 네이버 오픈API의 API HUB 이관(2026), 공정위 지침 개정(2024-12, 표기는 제목·첫 부분), 구글·네이버의 대량 생성 제재가 설계에 반영되지 않았다.

**살린 것:** `00_요구사항.md`(사용자 원문 정리), 경험을 지어내지 않는 원칙, 이미지마다 역할을 정하는 원칙, "AI스러움" 수정 표의 취지. 이 원칙들은 [05 생성 규칙](05_생성규칙.md)에 흡수했다. 지운 원문은 git 이력 `56b85b7`에 남아 있다.

## 3. "어떤 글도 들어갈 수 없다"의 실체

Codex 말은 맞다. 이 클라우드 실행 환경은 조직 네트워크 정책으로 아래 주소를 막는다 (2026-10-15 Claude도 직접 확인, 프록시 403).

`naver.com` · `blog.naver.com` · `search.naver.com` · `datalab.naver.com` · `tistory.com` · `search.daum.net` · `trends.google.co.kr` · `youtube.com` · `brunch.co.kr` · 위키백과 · 대부분의 언론사

열리는 곳은 GitHub와 **웹 검색 도구**다. 검색 도구는 원문 대신 검색엔진이 요약한 결과와 발췌를 돌려준다. 그래서 이번 재조사는 이렇게 했다.

- 4개 갈래(트렌드 신호 / 국내 인기 글 패턴 / 플랫폼 정책·법 / 기술 구조)를 동시에 검색했다. 언론 기사, 체험단 공고, 공식 문서 발췌, GitHub 저장소를 근거로 썼다.
- **원문을 열어 센 것이 아니다.** 각 문서에 확인 수준(발췌 / 원문)을 적었다.
- 국내 인기 글을 직접 열어 사진 수·캡션·이모티콘을 세는 작업은 **사용자 PC의 브라우저**에서만 가능하다. 방법은 [03 문서 6절](03_국내글_패턴과_정책.md#6-다음에-pc-브라우저로-할-표본-조사)에 있다.
