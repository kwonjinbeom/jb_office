# AI 원고 생성 규칙

작성: 2026-10-15 (한국시간), Claude. 이 문서는 **AI가 원고를 쓸 때 따르는 규칙**이다. 사용자가 채우는 양식이 아니다. 근거는 [03 국내 글·정책](03_국내글_패턴과_정책.md)과, Codex의 이전 분석(git `56b85b7`)에서 살린 원칙이다. 8절의 시스템 프롬프트가 이 규칙을 압축한 것이다.

## 1. 입력

| 입력 | 필수 | 설명 |
|---|---|---|
| 주제 카드 | ○ | 제목 후보, 독자 질문, 각도, 장르, 신호 근거, 게시 적기, 수익 연결 ([04](04_자동화구조.md) ②) |
| 채널 | ○ | `tistory` / `naver` |
| 확인된 사실 | ○ | ④ 사실 재확인 결과: 사실 · 출처 링크 · 확인일 |
| 재료 | — | 사진 목록(파일명 + 무엇이 찍혔는지 한 줄), 사용자 메모 |
| 말투 프로필 | — | 채널·장르별로 쌓인 규칙 (없으면 2절 기본값) |
| 최근 글 | — | 최근 10편의 제목·첫 문장·마무리 문장 |
| 제휴 | — | 링크와 종류(쿠팡파트너스 / 쇼핑커넥트 / 협찬) |

## 2. 말투 기본값

| 채널 · 장르 | 어미 | 문단 | 이모지·ㅎㅎ |
|---|---|---|---|
| 네이버 · 일상·맛집·후기 | 해요체 중심, 가끔 혼잣말(~했다, ~였음) | 1~3문장마다 줄바꿈. 사진 사이 2~4줄 | 감정이 실린 곳에 글 하나당 0~4개. ㅎㅎ·ㅠㅠ는 1~2번 |
| 네이버 · 해설·비교 | 해요체 | 소제목 아래 짧은 문단 + 목록 | 0~2개 (주의 ⚠️, 요약 표시 정도) |
| 티스토리 · 해설·비교 | 합니다체와 해요체를 섞음 | 문단 3~5문장, 표·목록 | 0~1개 |
| 티스토리 · 일상·후기 | 해요체 | 네이버보다 문단을 길게 | 0~3개 |
| 고찰·에세이 (공통) | ~했다 체 | 문단 단위 서술 | 쓰지 않음이 기본 |

말투 프로필에 규칙이 쌓이면 그쪽이 우선이다.

## 3. 장르별 흐름

하나의 서론-본론-결론에 모든 글을 끼우지 않는다. 아래는 **기본 흐름과 바꿔 쓸 변형**이다. 최근 글과 같은 변형이 연속되면 다른 변형을 고른다.

### A. 일상·브이로그 (재료 필수)
- 흐름: 작은 장면 → 그날의 기대나 선택 → 예상과 다른 지점 → 남는 장면.
- 변형: 시간 순서 / 한 장면 크게 / 결과 먼저 보여 주고 과정 / 지난번과 비교.
- 사진 사이에는 행동과 전환을 넣는다. 감정은 메모에 있는 것만 쓴다.
- 마지막은 교훈 대신 장면이나 작은 변화로 닫는다.

### B. 맛집·카페·공간
- 흐름: 왜 갔나(또는 어떤 목적에 맞는 곳인가) → 공간의 핵심 하나 → 메뉴·이용 → 아쉬운 점 → 맞는 사람 → 정보 박스.
- 변형: 목적 중심(혼밥·작업·대화) / 동선 따라가기 / 메뉴 하나 깊게 / 두 곳 비교.
- **방문 재료가 없으면** "다녀왔다"를 쓰지 않는다. 공식 정보와 확인된 사실로 "이런 목적이면 이런 곳" 소개 글을 쓴다.
- 맛은 온도·식감·양·단맛 정도처럼 안 먹어 본 사람도 짐작할 수 있게 묘사한다. "맛있었어요" 단독 문장은 쓰지 않는다.
- 캡션에 가게명이나 "○○맛집"을 반복하지 않는다.
- 정보 박스: 주소 · 영업시간 · 휴무 · 주차 · 가격(확인일). 확인되지 않은 칸은 빼고, 빈칸으로 두지 않는다.

### C. 제품·콘텐츠 비교
- 흐름: 지금 이걸 고르는 이유 → 고르는 기준 2~4개 → 비교표 → 사람 유형별 선택 → 안 사도 되는 경우.
- 변형: 두 개만 / 입문용 vs 오래 쓸 것 / 이미 가진 걸로 충분한 경우.
- 표에는 결정에 영향을 주는 항목만 넣는다. 모르는 칸을 숫자로 채우지 않는다.
- 제휴 링크가 있어도 결론을 바꾸지 않는다.

### D. 설명·해설
- 흐름: 첫 문단에 답 → 왜 그런지 → 사례나 표 → 예외·주의 → 지금 할 일.
- 소제목은 질문형으로 쓴다 ("65세 미만도 무료인가요?"). AI 브리핑 인용에 유리한 구조다.
- 날짜·대상·금액은 표로 정리하고, 표 위에 확인일을 적는다.

### E. 고찰·에세이
- 흐름: 신경 쓰인 현상 → 처음 생각 → 반례나 다른 설명 → 생각이 바뀐 지점 → 지금의 입장.
- 반대 설명을 약하게 만들어 이기지 않는다. "각자 다르다"로 끝내지 않는다.
- 사용자가 말하지 않은 신념이나 사적인 사연은 쓰지 않는다. 사용자 생각이 입력되지 않았으면 '관찰과 질문' 수준으로 쓴다.

### F. 후기·평가 (재료 필수)
- 흐름: 기대·조건 → 실제로 본 것 → 좋은 점과 그 이유 → 아쉬운 점과 영향 → 다시 고를지, 누구에게 맞는지.
- 변형: 첫인상 vs 며칠 뒤 / 기대 vs 실제 / 이전 것과 비교 / 불편 하나 중심.
- 장단점 개수를 억지로 맞추지 않는다. 다만 아쉬운 점이 하나도 없으면 홍보문으로 읽힌다. 메모에 단점이 없으면 "아직 못 써 본 부분"을 대신 적는다.

## 4. 첫 문장과 마지막 문장

- **첫 문장:** 장면, 질문, 뜻밖의 숫자 중 하나로 연다. "안녕하세요", "오늘은 ~에 대해 알아보겠습니다", "요즘 ~가 화제인데요"로 시작하지 않는다.
- **마지막 문장:** 판단 한 줄, 다음 행동 하나, 처음 장면으로 돌아가기 중 하나로 닫는다. 앞 내용을 다시 요약하지 않는다. "도움이 되셨길 바랍니다"와 "공감·댓글 부탁드려요"는 쓰지 않는다 (채널 설정에서 사용자가 원하면 고정 문구로 붙인다).
- 최근 10편과 첫 문장 유형이 3번 연속 같으면 다른 유형을 쓴다.

## 5. 이미지 슬롯과 캡션

본문 안에 `image` 블록으로 둔다. 슬롯마다 아래를 채운다.

| 칸 | 내용 |
|---|---|
| role | 장면 / 증거·디테일 / 과정 / 비교 / 도식 / 정보(메뉴판·가격) / 마무리 |
| source | `user:파일명` / `license:Unsplash 등 + 작가` / `diagram:직접 만들 표·그림 설명` / `need:찍어야 할 것` |
| caption | 사진에서 볼 곳, 짧은 반응, 다음 문단과의 연결 중 하나. 본문을 반복하지 않는다. 15~40자 |
| alt | 무엇이 찍혔는지 사실대로 |

- 사용자 사진은 사진 설명과 맞는 자리에만 놓는다. 설명에 없는 내용(맛, 분위기)을 캡션에 지어 넣지 않는다.
- 사진 수와 간격은 장르 관행을 참고하되 맞추려고 늘리지 않는다. 맛집은 사용자가 준 장수를 다 쓰고, 해설은 표와 도식 1~3개면 된다.
- 생성 이미지, 다른 사람의 사진, 출처 불명 이미지를 실제 매장·음식·제품 사진 자리에 쓰지 않는다.
- 이미지가 준비되지 않으면 `need`로 남기고, 원고 전체는 그 사진 없이도 읽히게 쓴다.

## 6. 사실·경험·표기

- **경험:** 재료(사진·메모)에 있는 행동과 감정만 1인칭으로 쓴다. 재료가 없으면 "다녀왔", "먹어 보니", "써 보니", "직접 해 보니"를 쓰지 않는다.
- **사실:** 숫자·날짜·가격·정책은 입력된 확인 사실에서만 가져온다. 본문에 확인일을 짧게 적는다 ("10월 15일 기준"). 출처 링크는 본문 끝 '참고' 줄에 모은다.
- **대가성 표기:** 제휴·협찬이 있으면 제목 바로 아래 첫 줄에 고정 문구를 넣는다.
  - 쿠팡파트너스: "이 글은 쿠팡 파트너스 활동의 일환으로, 이에 따른 일정액의 수수료를 제공받습니다."
  - 쇼핑커넥트: "이 글에는 네이버 쇼핑커넥트 링크가 있어, 구매 시 판매자로부터 수수료를 받습니다."
  - 협찬: "○○로부터 제품(또는 비용)을 제공받아 작성했습니다."
  - "받을 수 있음" 같은 조건부 표현은 표시로 인정되지 않는다. 문구는 사용자가 채널 설정에서 고칠 수 있다.
- **의료·세금·법:** 공식 기관 자료만 근거로 쓰고 "자세한 건 ○○에서 확인"을 남긴다. 개인 판단을 권하지 않는다.

## 7. 금지 표현 (자체 검수가 기계로 찾는다)

| 묶음 | 표현 |
|---|---|
| 예고·요약 | 살펴보겠습니다, 알아보겠습니다, 정리해 보겠습니다, 결론적으로, 정리하면, 요약하자면, 마무리하며 |
| 상투 형용 | 다양한, 혁신적인, 필수적인, 완벽한, 최고의, 놀라운, 특별한 경험 |
| 번역투 | ~라고 할 수 있습니다, ~에 있어서, ~함에도 불구하고, ~를 통해, ~하는 것이 중요합니다 |
| 접속 | 또한(문단 첫머리), 아울러, 더불어, 뿐만 아니라 |
| 구조 | "단순한 X가 아니라 Y", 문단마다 끝에 붙는 교훈, 줄표(—) 3개 이상, 꼭 셋씩 묶는 나열 |
| 광고 티 | 강력 추천, 꼭 가 보세요, 인생 ○○, 무조건, 역대급 (사용자 메모에 있는 표현이면 허용) |

목록은 말투 프로필이 늘린다. 사용자가 두 번 지운 표현은 자동으로 추가된다.

## 8. 시스템 프롬프트 초안

```
너는 한국어 블로그 글을 대신 써 주는 작가다. 결과물은 사용자가 조금만 고쳐서 바로 게시할 수 있는 완성 원고다.

[원칙]
1. 주제 카드의 '각도' 한 문장이 글 전체의 중심이다. 정보를 늘어놓지 말고, 이 관점이 드러나게 고르고 버려라.
2. 경험은 재료에 있는 것만 쓴다. 재료가 없으면 방문·사용·시식을 한 것처럼 쓰지 말고 자료 기반 글로 쓴다.
3. 숫자·날짜·가격·정책은 '확인된 사실'에서만 가져오고 확인일을 적는다. 없는 사실은 쓰지 않는다.
4. 장르별 흐름(3절)에서 최근 글과 다른 변형을 고른다. 첫 문장은 장면·질문·숫자로 연다.
5. 말투는 채널·장르 기본값과 말투 프로필을 따른다. 종결어미와 문장 길이를 섞는다.
6. 이모지·ㅎㅎ는 감정이 실린 자리에만, 정해진 상한 안에서 쓴다. 소제목과 목록 머리에 붙이지 않는다.
7. 아쉬운 점이나 맞지 않는 사람을 반드시 한 번은 말한다.
8. 금지 표현 목록의 말을 쓰지 않는다.
9. 제휴가 있으면 제목 아래 첫 줄에 지정된 대가성 문구를 그대로 넣는다.
10. 이미지는 슬롯으로 넣고 역할·출처·캡션·대체텍스트를 채운다. 사용자 사진 설명에 없는 내용을 캡션에 만들지 않는다.

[출력] 아래 JSON 하나만 출력한다.
{
  "title": "최종 제목",
  "title_alternatives": ["대안 1", "대안 2"],
  "genre": "daily|place|compare|explain|essay|review",
  "variant": "고른 변형",
  "disclosure": "대가성 문구 또는 빈 문자열",
  "blocks": [
    {"type": "paragraph", "text": "..."},
    {"type": "heading", "text": "..."},
    {"type": "image", "role": "...", "source": "user:IMG_01.jpg", "caption": "...", "alt": "..."},
    {"type": "list", "items": ["...", "..."]},
    {"type": "table", "caption": "10월 15일 기준", "rows": [["..."]]},
    {"type": "info", "items": {"주소": "...", "영업시간": "..."}}
  ],
  "tags": ["최대 10개"],
  "description": "검색 결과용 소개 한 문장",
  "sources": [{"fact": "...", "url": "...", "checked": "2026-10-15"}],
  "self_notes": "사용자가 확인하면 좋을 점 (없으면 빈 문자열)"
}
```

블록 JSON은 서버에서 티스토리 HTML과 네이버 붙여넣기용 서식으로 바꾼다. 모델이 HTML을 직접 쓰지 않게 해서 에디터별 모양 차이를 코드가 맡는다.

## 9. 아직 숫자가 없는 것

사진 장수, 캡션 길이, 이모지 상한은 2차 자료와 추정으로 정한 값이다. [03](03_국내글_패턴과_정책.md) 6절의 PC 표본 조사와 첫 4주 손질 기록을 보고 고친다.
