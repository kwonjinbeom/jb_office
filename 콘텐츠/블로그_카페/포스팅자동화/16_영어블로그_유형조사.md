# 영어 블로그 — 영어권 독자가 찾는 유형 (2026-10-26)

근거 등급: [공식] 정부·구글 문서 · [연구] 조사·논문 · [2차 보도] 언론·업계 글 · [경험담] 블로거 개인 경험 · [관찰] 이번 검색에서 직접 본 것 · [추정] 근거를 보고 내린 판단

## 결론

- **강점은 하나다. "한국어 공지를 영어보다 먼저 읽는다."** 2026년에 외국인 여행 규칙이 많이 바뀌었다(입국·기차·버스·교통카드·택스리펀). 영어 안내글은 서로 날짜가 다르고 낡은 것이 많다. [관찰]
- **시험할 주제 두 개, 덤 하나.** ① 한국 여행 "바뀐 것" 실무 안내 ② 외국인용 축제·계절 달력(차 없이 가는 법 포함) ③ (덤) 올리브영 세일 달력·택스리펀.
- **피할 것.** 동물 상식, 한식 레시피, K-드라마 공개 일정, 코스피 일일 시황, 한국 주택·청년 정책 번역. 경쟁이 꽉 찼거나, 한국 거주자라는 강점이 없거나, 읽는 사람이 외국인이 아니다.
- **기대치는 낮게.** AI 요약(AI Overviews)이 뜨면 클릭이 크게 준다. 여행 블로그 트래픽은 2022년보다 크게 줄었다. 12주 안에 수익은 기대하지 말고 "검색 노출·국가별 독자"만 본다. [연구][2차 보도]
- **구조.** 한국어 글과 같은 카테고리에 섞지 않는다. 시험은 별도 영어 블로그(Blogger)로 한다. 번역 쌍이 아니므로 hreflang 은 필요 없다. [공식]
- **품질 점검.** 영어를 직접 읽지 않고, "한국어 사실표 + 문단별 한국어 요약 + 다른 번역기 역번역 + 숫자 자동 대조"로 확인한다.

## 2. 통하는 형식과 지금 구글

### 구글이 보는 것 [공식]

- "직접 경험과 깊은 지식이 보이는가", "남의 말을 요약만 하지 않는가"를 묻는다. https://developers.google.com/search/docs/fundamentals/creating-helpful-content
- 경고 신호: 여러 주제를 마구 쓰기, 글자 수 맞추기, 전문성 없이 틈새 진입, 자동화로 대량 생산.
- 누가(글쓴이 표시), 어떻게(AI 사용을 밝힘), 왜(사람을 돕기 위해)를 본다.
- 스팸 정책: AI·번역 같은 자동 변환으로 가치 없는 글을 대량으로 만들면 "대량 콘텐츠 남용". AI·번역 자체를 금지하지는 않는다(2026-08-28 개정). https://developers.google.com/search/docs/essentials/spam-policies

### 검색 화면 변화

- AI 요약이 뜨면 일반 결과 클릭 8%, 안 뜨면 15%(퓨리서치, 미국 성인 900명). [연구] https://www.pewresearch.org/short-reads/2025/07/22/google-users-are-less-likely-to-click-on-links-when-an-ai-summary-appears-in-the-results/
- 아렙스: AI 요약 있을 때 1위 클릭률 34.5% 감소(2025-04), 2025-12 자료로는 약 58% 감소 추정. [연구] https://ahrefs.com/blog/ai-overviews-reduce-clicks/ · https://ppc.land/googles-ai-summaries-now-swallow-58-of-clicks-that-once-went-to-websites/
- AI 요약은 처음엔 정보형 질문 위주였고, 2025년 동안 상업·거래형 질문으로 넓어졌다. [연구] https://www.semrush.com/blog/semrush-ai-overviews-study/
- 레딧: 구글 "토론·포럼" 칸의 83.9%를 차지. 2025년 8월 이후 노출은 다소 꺾임. [연구] https://www.sistrix.com/blog/reddit-domain-analysis/ · https://newsdashboard.com/en/revisiting-reddit-new-analysis-highlights-reddits-remarkable-visibility-growth-on-googles-serps/
- 여행 블로그 100곳 표본: 2022-04 → 2026-04 중앙값 74% 감소(업체가 인용, 원자료 미확인). [2차 보도] https://www.getchatads.com/blog/add-ai-assistant-travel-blog/
- 여행 블로거들은 "구글 의존을 줄이고 단골 독자를 만들라"고 말한다. [경험담] https://www.dangerous-business.com/how-google-and-ai-are-killing-travel-blogs-like-mine/ · https://www.novo-monde.com/en/ai-impact-travel-blog/

### 그래서 쓸 형식 [추정]

| 형식 | 쓰는 이유 |
|---|---|
| 단계별 안내(스크린샷·표) | AI 요약이 한두 줄로 대신 못 함 |
| "바뀐 것" 갱신 글(맨 위 "Last updated" 날짜) | 날짜가 생명. 낡은 영어 글보다 앞선다 |
| 비용·선택 비교표 | 기후동행카드 vs 티머니처럼 계산이 필요한 질문 |
| 살아 있는 달력(허브 글 1개를 계속 고침) | 축제·세일 일정. 새 글을 늘리지 않고 한 주소에 쌓음 |
| 대중교통 경로(서울 출발, 차 없이) | 외국인 대부분 차가 없음. 국내 글에 없는 부분 |

- 피할 형식: "Top 10 ○○" 일반 목록, 문화 설명 장문, 정의형 글. AI 요약이 바로 답한다.
- 직접 경험 표시: 사용자가 찍은 사진(역 키오스크, 축제장 안내판)을 넣는다. 가 보지 않은 곳을 "가 봤다"고 쓰지 않는다.

## 3. 12주 시험 — 주제 두 개와 덤 하나

### 왜 이 셋인가

- **A. 여행 실무 "바뀐 것"**: 수요가 가장 크다. 한국어 원문을 먼저 읽는 강점이 바로 쓰인다. 미국·영국·호주 독자가 출발 전에 찾는다.
- **B. 축제·계절 달력**: 지금 매일 하는 국내 축제 조사를 다시 쓴다. 번역이 아니라 외국인용 새 구성(서울에서 가는 법, 영어 안내 여부, 해외카드 결제)으로 쓴다.
- **C. (덤) 올리브영 세일·택스리펀**: 수요는 크지만 경쟁도 세다. 세일 달력과 환급 절차만 쓴다. 제품 후기는 쓰지 않는다.

- 언어마다 다른 주소를 쓴다(쿠키·브라우저 설정으로 바꾸지 않음).
- 한 페이지엔 한 언어. 본문과 메뉴(내비게이션)도 같은 언어로.
- 구글은 페이지 언어를 보이는 본문으로 판단한다(lang 속성·주소로 판단하지 않음).
- hreflang 은 같은 글의 언어별 판(번역 쌍)을 이어 줄 때 쓴다. 새로 쓴 영어 글엔 필요 없다.
- 하위 폴더(`/en/`)도 공식 선택지다. 장점: 설치 쉬움. 단점: 사이트 분리가 어렵다.

### 선택지 비교

| | 별도 Blogger 영어 블로그 | 워드프레스 jinbaam.com/en/ |
|---|---|---|
| 시작 | 바로, 무료 | 카페24 관리형 설정 필요 |
| 한국어 사이트 영향 | 없음 | 실패한 영어 글이 본 사이트에 남음 |
| 메뉴·카테고리 | 처음부터 영어 | 영어 메뉴·카테고리·푸터를 따로 만들어야 함 |
| 도메인 힘 공유 | 거의 없음 | 공유됨 [2차 보도] |
| 나중에 옮기기 | 주소 바뀜(자체 하위 도메인 쓰면 줄일 수 있음) | 안 옮겨도 됨 |

- **시험 12주는 별도 Blogger 영어 블로그를 권한다.** 워드프레스는 1년 빌드업 중인 한국어 수익 블로그다. 주제(한국 여행 영어)가 섞이면 사이트 성격이 흐려진다. [추정]
- 가능하면 처음부터 `en.자기도메인` 같은 하위 도메인을 Blogger 에 연결한다. 나중에 옮겨도 주소를 지킬 여지가 생긴다. [추정]
- 기존 한국어 Blogger 블로그에 영어 글을 끼우지 않는다.
- 하위 도메인·블로그스팟은 본 도메인과 따로 평가되는 편이다. [2차 보도] https://www.smartinsights.com/search-engine-optimisation-seo/internal-linking-strategy/which-is-best-for-blog-seo-subdomain-or-subfolder/

### 한 카테고리에 한국어·영어 번갈아 올리기 → 하지 않는다

- 글 하나하나는 언어가 하나라 구글 색인엔 큰 문제가 없을 수 있다. [추정]
- 하지만 카테고리 목록·메뉴·사이드바가 두 언어로 섞인다. 구글이 피하라는 "한 페이지에 여러 언어"가 목록 페이지에서 생긴다. [공식 기준에 비춘 추정]
- 영어 독자는 한국어 목록을 보고 바로 나간다. 한국어 독자도 마찬가지. [추정]
- 워드프레스를 쓰게 되면: `/en/` 전용 카테고리, 영어 메뉴, 글마다 `lang="en"`, 한국어 글과 내부 링크 섞지 않기.

## 5. 영어를 못 읽는 운영자의 품질 점검 절차

### 원칙

- 사용자는 영어 문장이 아니라 **한국어로 된 사실과 구조**를 확인한다.
- 역번역(영어→한국어 되돌리기)은 큰 오류 찾기용일 뿐이다. 연구상 품질 예측력은 약하다. [연구] https://graphsearch.epfl.ch/en/concept/11336666 · https://arxiv.org/pdf/2604.12911

### 글 하나당 순서

| 단계 | 누가 | 무엇을 |
|---|---|---|
| 1. 기획표 | Claude → 사용자 | 한국어로: 독자 질문, 결론 한 줄, 넣을 사실, 원문 주소 |
| 2. 사실표 | Claude | 날짜·금액·시간·역 이름을 표로. 칸마다 한국어 원문 주소 |
| 3. 영어 원고 + 문단별 한국어 요약 | Claude | 영어 문단 옆에 한국어 한두 줄 요약을 나란히 |
| 4. 사실 대조 | 사용자 | 사실표의 숫자를 한국어 원문에서 확인(5~10분) |
| 5. 숫자 자동 대조 | 스크립트 | 영어 원고 속 숫자·날짜가 모두 사실표에 있는지 기계로 확인 |
| 6. 역번역 | 다른 번역기 | 파파고나 DeepL 로 영어→한국어. 3단계 요약과 뜻이 다른 문단만 표시 |
| 7. 문장 점검 | 도구 + 다른 AI | LanguageTool(무료) 문법 검사. 다른 AI에게 "미국인 편집자로서 어색한 표현만 지적" 요청 |
| 8. 화면 확인 | 사용자 | 사진·표·링크가 제대로 보이는지, 맨 위 "Last updated" 날짜 |

- 영어 표기 규칙(원고 규칙에 넣기): 날짜 `Nov 26, 2026`, 금액 `₩15,000 (about $11)`, 역 이름은 공식 영문 표기(코레일·서울교통공사 표기). [추정]
- "Fighting", "skinship" 같은 한국식 영어 금지 목록을 둔다. [추정]
- 처음 3~5편은 원어민 교정(유료 교정 서비스)을 한 번 받아 Claude 규칙을 고친다. 이후엔 가끔만. [추정]
- 글마다 글쓴이 소개(한국 거주 운영자)와 "AI 도움으로 작성, 원문 확인" 문구를 넣는다. 구글이 묻는 "누가·어떻게"에 답한다. [공식] https://developers.google.com/search/docs/fundamentals/creating-helpful-content
