# 티스토리 글쓰기

메뉴: **블로그·카페 → 티스토리 글쓰기** (`/blog/writing/`, 앱 `apps/writing`).

2026-10-15 사용자 지시로 예전 구성(내 원고·템플릿·작성 설정, AI 초안·검수·내보내기)과 그 데이터를 모두 지우고, 글 한 편이 세 화면을 옮겨 다니는 구조로 바꿨다.

## 세 화면

| 화면 | 주소 | 들어 있는 것 | 상태 칸 |
|---|---|---|---|
| 임시 템플릿 | `/blog/writing/` | 일단 뽑아 둔 템플릿 | 없음 |
| 검토 템플릿 | `/blog/writing/review/` | 쓸지 따져 보고 손보는 템플릿 | 검토: 미검토 · 검토 중 · 검토 완료 |
| 포스트 관리 | `/blog/writing/posts/` | 실제로 쓰고 발행할 글 | 작성: 미작성 · 작성 중 · 작성 완료 / 발행: 미발행 · 발행 완료 |

- 이름 규칙: **[정해진 정도] + [대상]**. 화면을 늘릴 때도 같은 규칙을 따른다 (예: 보관 템플릿).
- 목록 칸: 제목 · 내용(요약, 없으면 본문 앞부분) · 화면별 상태 · 만든 날(임시) / 수정일(검토·포스트) · 이동 버튼.

## 옮기기 규칙

- 한 칸씩만 옮긴다: 임시 ↔ 검토 ↔ 포스트. 임시에서 포스트로 바로 가지 않는다.
- 행마다 버튼이 있고, 체크한 여러 건을 위쪽 버튼으로 한꺼번에 옮길 수도 있다.
- 옮겨도 상태값은 지우지 않는다. 되돌아오면 하던 상태 그대로다.
- **발행 완료한 포스트는 검토로 되돌리지 않는다.** 발행을 미발행으로 바꾸면 다시 옮길 수 있다.
- 목록에서 '발행 완료'를 누르면 발행일이 비어 있을 때 오늘 날짜가 들어간다. 발행 주소는 글을 열어 적는다.

## 데이터

- 모델 하나: `Post` (`stage` = temp/review/post, `review_status`, `write_status`, `publish_status`, `published_url`, `published_on`).
- migration `0002_post_pipeline` 이 예전 표(Draft·DraftRevision·WritingTemplate·WritingProfile)를 지우고 AppSetting 의 `writing_*` 설정(AI 키·모델)도 지운다. **서버에서 `migrate` 필요.**
- 예전 원고와 연결돼 있던 블로그·카페 콘텐츠(`content.Content`)는 지우지 않는다. 사용자가 직접 쓴 글일 수 있어서다.
