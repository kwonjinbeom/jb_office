# 공통 휴지통

일반 데이터는 원래 행의 `deleted_at` 하나로 삭제 상태와 시각을 표시한다.
기본 `objects` 조회는 삭제 행을 제외하고, 복원은 같은 행의 값을 `NULL`로 바꾼다.
PK·본문·기존 FK는 그대로이며 본문/이미지를 휴지통에 복사하지 않는다.

- 모든 사용자 데이터 목록에 작은 삭제 버튼과 선택 작업을 제공한다.
- 아이디어·폴더·대분류처럼 하위 자료를 소유한 항목은 하위 행도 같은 시각으로 숨긴다.
  함께 숨긴 PK 목록만 보관하며, 앞서 따로 삭제한 하위 자료까지 복원하지 않는다.
- 휴지통은 이름·위치·삭제일·만료일만 50건씩 조회한다. 선택 복원과 검색을 지원한다.
- 삭제 직후 알림에서 되돌릴 수 있다. 삭제 상태를 유지한 항목은 7일 후 복원이 차단된다.

## 만료 정리

별도 서버 설정 없이 정상 페이지 접근 시 한 시간에 최대 한 번, 만료 항목 50묶음씩 정리한다.
여러 WSGI 프로세스에서도 DB의 작은 시간 값으로 중복 실행을 제한한다.
접속이 없는 동안에는 다음 접근 때 처리하므로 정확히 만료 시각에 실행되는 예약 작업은 아니다.
활성 하위 자료나 아직 7일이 지나지 않은 하위 자료를 연쇄 삭제할 가능성이 있으면 정리를 보류한다.
필요한 경우 `manage.py purge_trash`로 만료 항목을 일괄 정리할 수도 있다.

Git에서 읽는 일일 아이디어·문서는 화면 제외 키만 보관한다.
7일 이내 복원하면 제외 키가 해제되며, 만료 후에는 작은 키를 남겨 재등장을 막는다.
원본 Git 파일은 삭제하지 않는다. 문서로 동기화되는 논의도 같은 방식으로 재수입을 막는다.

## 스키마와 검증

18개 모델에 nullable 인덱스 필드를 추가하고 공통 휴지통·원본 제외 키 테이블을 만든다.
마이그레이션 적용 자체로 기존 데이터를 삭제하거나 수정하지 않는다.
서버는 main 반영 시 자동 migrate 한다. 개발 검증은 임시 DB에서만 한다.

`manage.py test apps`는 삭제/복원, 같은 PK와 FK 유지, 계층 삭제,
7일 경계, 영구 삭제 보호, Git 재수입 방지, CSRF, 일괄 요청의 원자성,
목록 페이지 및 본문 조회 없는 휴지통 페이징을 검증한다.
