# 원고 체크리스트 (보조 claude 용)

글쓰기 루틴의 보조 claude 는 원고 1편을 맡아 이 파일만 읽고 쓴다. AGENTS.md·TISTORY_WRITER.md·05_생성규칙.md 같은 긴 문서는 읽지 않는다 (필요한 것은 여기 다 있다).
메인이 넘겨준 것: 분류 경로 · 사이트와 그 체크 · 사이트 컨셉·말투·구성·꼭 지킬 것 · 넣을 사이트 카테고리와 그 컨셉 · T번호와 폴더 이름 · 겹치면 안 되는 가까운 제목 · 그 분류의 '분류별 수요와 잘 쓰인 글' 단락 · 조사 출처(공통 + 그 분류).

## 0. 처음부터 그 사이트·카테고리 글로 (2026-10-20 사용자)
- 넘겨받은 사이트 컨셉과 카테고리 컨셉에 맞는 주제·각도만 고른다. 맞지 않으면 다른 주제로 바꾼다.
- 말투·구성·꼭 지킬 것은 처음 쓸 때부터 그대로 따른다. 나중의 변환은 플랫폼 포맷 다듬기와 사실 재점검만 한다.
- 아래 4. 본문 규칙과 사이트 템플릿이 다르면 사이트 템플릿을 따른다.

## 1. 주제
- 분류의 방향·독자의 질문 + 넘겨받은 '분류별 수요' + 오늘 조사로 주제 하나와 각도 한 문장을 정한다.
- 넘겨받은 제목, 원고 폴더(`콘텐츠/블로그_카페/포스팅자동화/원고/`)의 같은 분류 원고와 겹치지 않게 한다 (폴더 이름을 Glob 으로 훑으면 된다).

## 2. 조사
- 넘겨받은 조사 출처를 먼저 연다: 트렌드·순위는 '공통'에서, 사실·숫자·일정은 그 분류의 공식 출처에서. '읽기'가 브라우저인 곳은 playwright 로 연다.
- 고정 출처에 없는 새 소식·빈 곳은 WebSearch 로 채운다 (오늘·이번 주 트렌드, 많이 찾는 말).
- 숫자·날짜·정책·가격은 공식 출처(기관·제조사·서비스 공지)를 WebSearch·WebFetch 로 확인한다. 확인 못 한 것은 쓰지 않거나 `확인 못 함: <주소>` 로 적는다.
- 안 열리는 곳은 넘어가고 다른 출처로 간다. 로그인·댓글·글쓰기는 하지 않는다.

## 3. 원고 파일 — `콘텐츠/블로그_카페/포스팅자동화/원고/<T번호_짧은이름>/원고.md`
맨 위부터 이 순서 (최근 원고 하나를 열어 보면 같은 모양이다):
1. `# [원고] T번호 · 제목`
2. `사이트: <사이트 이름>` / `분류: <대분류> > <중분류> > <소분류>` (소분류가 없으면 중분류까지) — 원고 가져오기가 이 두 줄을 읽는다
3. 제작 정보 표: 형식(장르·말투) · 채널 · `넣을 카테고리`(사이트 › 카테고리) · `맞춘 컨셉`(한 줄) · 각도 · 게시 적기 · 대가성 표기 · 겹침 확인 · `참고 조사`(트렌드 출처 · 확인한 공식 출처 · 가져온 점 한 줄)
4. `## 손질하면 좋아지는 곳 (사용자 몫)`: 내 경험 한 줄·사진·제휴 링크처럼 AI 가 못 하는 것 2~3개
5. `## 확인한 사실` 표: 사실 · 출처 링크 · 확인
6. `---` 뒤 `<!-- 본문 시작 -->`, 바로 다음 줄에 `# 제목` (블로그에 올릴 제목. 원고 가져오기가 이 줄을 제목으로 쓴다) … 본문 … 끝에 `참고:` 출처 줄 (확인 날짜) … `<!-- 본문 끝 -->`
7. `---` 뒤 `태그: ` (쉼표, 10개 이내) 와 `소개: ` (검색 결과용 한두 문장)

## 4. 본문
- **정보성 글은 꼭 필요한 내용만 짧게 (2026-10-20 사용자).** 독자가 지금 알아야 할 결론·숫자·날짜·조건·할 일만 남긴다.
  - 소제목 3~5개, 표는 1~2개. 배경·역사·용어 풀이·일반론, 같은 말 되풀이, 앞 내용 요약은 쓰지 않는다.
  - 상위 글이 소제목 10개·FAQ 20개라도 따라 늘리지 않는다. FAQ 는 꼭 필요할 때 3개 이내.
  - 문단은 2~3문장. 한 문단에 정보 하나. 빼도 독자가 손해 보지 않는 문장은 뺀다.
- **결론은 본문과 구분해 맨 위 인용 상자(`>`) 하나에 쓴다 (2026-10-20 사용자).** 1~3문장, 핵심 수치·날짜 포함. 인용 상자 안에서는 굵게를 쓰지 않는다.
  - 하지 않는 것: '요약'·'결론부터'·'핵심 정리'·'📌' 같은 이름표를 단 뒤 굵은 글씨로 몰아 쓰기 (사용자: 너무 이상하다), 불릿 요약 박스.
  - 인용 상자 다음 본문은 바로 내용으로 들어간다 (결론을 다시 되풀이하지 않는다). 본문에서 굵게(**)는 꼭 짚을 숫자 하나 정도에만. "안녕하세요", "오늘은 ~ 알아보겠습니다", "요즘 ~가 화제인데요"로 시작하지 않는다.
- 해설은 질문형 소제목, 날짜·대상·금액은 표 (표 위에 확인일). 비교는 고르는 기준 2~4개 → 비교표 → 사람 유형별 선택 → 안 사도 되는 경우.
- 차별화: 실제 숫자·표, '우리 집/내 기기/내 상황'별 한 줄, 되돌리기·막혔을 때 연락처 같은 실행 디테일, 과장어 대신 원리.
- 아쉬운 점이나 맞지 않는 사람을 한 번은 말한다. 마지막 문장은 판단 한 줄 또는 다음 행동 하나 (앞 내용 요약·"도움이 되셨길" 금지).
- 경험은 쓰지 않는다: "다녀왔", "먹어 보니", "써 보니", "직접 해 보니" 금지 (재료가 없다).
- 말투: 티스토리 해설·비교는 합니다체+해요체, 개발 글은 ~다 체, 네이버는 해요체. 이모지는 0~2개.
- 사진 자리는 `[사진] 설명`(사용자 사진), 도식 자리는 `[그림] 설명`. 사진 없이도 읽히게 쓴다.
- 제휴가 있으면 제목 바로 아래 첫 줄에 대가성 문구, 없으면 `<!-- 제휴가 있으면 이 줄에 대가성 문구 -->`.
- 금지 표현: 살펴보겠습니다·알아보겠습니다·결론적으로·정리하면 / 다양한·혁신적인·완벽한·최고의·놀라운 / ~라고 할 수 있습니다·~에 있어서·~를 통해·~하는 것이 중요합니다 / 문단 첫머리 '또한'·아울러·더불어 / "단순한 X가 아니라 Y" / 강력 추천·꼭 가 보세요·무조건·역대급.

## 5. 끝
- 원고 파일만 만든다. git 커밋·push 와 분류 변경 파일은 메인이 한다.
- 메인에게는 한 줄만 돌려준다: `T49 저장 완료 · <제목>` (못 쓰면 `T49 못 씀 · <이유 한 줄>`). 조사 내용·본문을 다시 붙이지 않는다.
