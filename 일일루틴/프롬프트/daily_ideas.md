# 일일 아이디어 루틴

안내문의 날짜·하루 양만큼 아이디어 후보를 찾는다.
매일 아침 7시 예약 실행(클라우드), 리스트의 '실행'(예약이 안 돌았을 때), '추가 실행'(더 찾고 싶을 때)이 이 md 를 똑같이 따른다.
안내문에 '이번에 할 것 (추가 실행)'이 있으면 그 개수·방향대로 한다. 그날 날짜.json 이 이미 있으면 덮어쓰지 말고 items 에 더하고 (id 는 겹치지 않게), 상세 문서도 이어 쓴다.

## 먼저 읽기
- AGENTS.md
- 시장조사/00_아이디어_조사방법.md

## 할 일
1. 안내문 '오늘의 자료 › 검색 표준'(최신판)에 맞춰 조사한다. 표준과 다르게 판단한 부분은 상세 문서 맨 위에 이유와 함께 적는다.
2. '오늘의 자료 › 지난 후보'와 시장조사/일일아이디어/*.json 의 지난 후보와 겹치지 않게 한다.
3. 조사는 WebSearch·WebFetch 로 한다. 안 열리는 출처는 상세 문서에 `확인 못 함: <주소>` 로 적고 다른 출처로 간다. 확인 못 한 숫자는 쓰지 않는다. 아래 '잘 되는 출처'(최신화가 쌓은 것)를 먼저 쓴다.
4. 결과 형식은 검색 표준의 요청문을 따른다 (날짜.json + 상세 조사 문서).
5. 끝나면 main 에 반영한다: `git pull --rebase origin main` 뒤 `git push origin HEAD:main`. main 으로 push 가 막히는 환경이면 지금 브랜치에 push 하고 main 으로 PR 을 만들어 바로 병합한다. 병합까지 해야 서버에 들어간다 (웹훅이 자동 반영).
