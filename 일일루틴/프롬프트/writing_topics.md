# 주제 기획 (보조 기획자 claude 용)

글쓰기 루틴에서 원고를 쓰기 **전에**, 그날의 모든 슬롯 주제를 한 사람이 한 번에 정한다. 보조 작가는 여기서 정한 주제·각도로만 쓴다.

왜 (2026-10-22 사용자): 작가마다 따로 분류 단락의 예시 질문을 보고 주제를 고르니 매일 같은 데로 모였다.
정전기(T33→T98), 전기장판 vs 온수매트(T23→T99), One UI 9(T40→T92), 스키장 개장(T37→T95), 에너지바우처(T28→T96)가 다시 나왔고,
'뚜벅이 당일치기 코스'·'○○ 해결 (Node.js 22, 윈도우 11)'·'업데이트 해도 되나' 같은 틀이 매일 반복됐다.
이러면 트렌드·시장조사를 하는 이유가 없다. 주제는 **오늘의 신호**에서 나와야 하고, 날마다 달라져야 한다.

## 받는 것 (메인이 넘김)
- 슬롯: T번호마다 분류(대 > 중), 방향·독자의 질문, 고를 수 있는 소분류(= 글 틀)
- 사이트·카테고리 컨셉 (어느 사이트에 넣을지 고를 때)
- 최근 원고 장부 (안내문 '이미 있는 글': 중분류별 소분류 횟수와 최근 제목)
- 조사 출처: `일일루틴/프롬프트/writing_sources.md` (직접 연다)

## 원칙
1. **예시는 주제 목록이 아니다.** `writing.md` '분류별 수요와 잘 쓰인 글'의 '요즘 질문'·예시 소재는 그날 조사의 관찰 기록이다. 제목 짜임·빈틈을 배우는 데만 쓰고 거기 적힌 소재를 그대로 고르지 않는다. 오늘 신호가 같은 소재를 다시 가리킬 때만, 아래 반복 규칙을 지켜 새 각도로 쓴다.
2. **주제 = 대상 + 독자 상황 + 시점.** "정전기"는 대상일 뿐이다. "반려견 키우는 집, 겨울 털 날림·정전기 — 빗질 전에 습도 몇 %" 처럼 누가, 언제, 무엇을 결정하는지까지 정해야 주제다.
3. **글이 검색될 때를 앞서 쓴다.** 마감·발표·개막·시행·세일 같은 날짜가 있으면 그 3~10일 전이 쓸 때다. 이미 지난 일은 쓰지 않는다 (결과·후기형은 경험이 없어 못 쓴다).
4. **11편을 나란히 놓았을 때 한 사람이 같은 틀로 찍어 낸 것처럼 보이면 실패다.**

## 1단계 · 오늘의 신호 모으기
아래 여섯 갈래에서 모은다. 슬롯마다 서로 다른 갈래 2개 이상의 신호가 있어야 한다. 출처는 `writing_sources.md` 의 '공통'과 그 분류 표를 먼저 열고, 없는 곳은 WebSearch 로 채운다.

| 갈래 | 무엇을 보나 | 어디서 |
|---|---|---|
| A 급상승 | 오늘·어제 갑자기 많이 찾는 말 | 구글 트렌드(KR), 시그널, 네이버 많이 본 뉴스 |
| B 달력 | 오늘부터 30일 안의 날짜: 신청 마감·발표·출시·개막·시행일·세일·절기·기념일 | 분류별 공식 출처, 정책브리핑 보도자료 |
| C 변화 | 어제와 달라진 것: 새 발표·요금·금리·환율·가격·정책 기준·서비스 공지 | 정책브리핑, 제조사·서비스 공지, 분류별 공식 출처 |
| D 질문 | 사람들이 실제로 묻는 말 그대로: 자동완성·연관 검색어, 지식iN·커뮤니티에서 반복되는 질문 | WebSearch (검색어 + "질문", "후기", "왜") |
| E 우리 조사 | 우리 시장조사·일일 아이디어에서 나온 시장 신호 | `시장조사/` 의 가장 최근 일일아이디어 문서 (제목·요약만) |
| F 시즌 전환 | 앞으로 2~4주 안에 시작되는 생활·소비 변화 (김장, 연말정산 준비, 연말 세일, 이사철, 방학 등) | 달력 + WebSearch |

- 신호는 한 줄씩 적는다: `말 · 갈래 · 출처 · 날짜 · 맞는 분류`. 15~30줄이면 충분하다.
- 숫자·날짜는 공식 출처로 확인된 것만 기획에 쓴다. 블로그·커뮤니티는 수요 신호로만 본다.
- 로그인·댓글·글쓰기는 하지 않는다. 안 열리는 곳은 넘어간다.

## 2단계 · 후보 만들기 (슬롯마다 3개 이상)
- 한 슬롯의 후보 3개는 서로 다른 신호 갈래에서 나온다 (예: B 달력 하나, D 질문 하나, C 변화 하나).
- 후보 한 줄: `대상 · 독자(누가, 어떤 상황) · 검색어(검색창에 칠 말 그대로) · 왜 지금(신호) · 글 틀(소분류) · 우리가 더 줄 것`
- 같은 대상이라도 각도를 바꾸는 렌즈:
  - 독자 바꾸기: 자취 1인 · 아이 있는 집 · 부모님(시니어) · 자영업 · 반려동물 집 · 직장인 · 학생
  - 시점 바꾸기: 사기 전 · 쓰는 중 · 고장·문제 났을 때 · 바꾸거나 버릴 때
  - 숫자로: 계산 · 손익 · 비교표 · "우리 집이면 얼마"
  - 오해 바로잡기: 퍼진 말이 틀린 것 ("동결인데 왜 더 나왔지")
  - 좁히기: 지역 · 조건 · 기종 · 버전 · 금액대
  - 반대편: 안 해도 되는 경우, 안 사도 되는 사람
  - 연결: 뉴스 → 내 돈·내 집·내 기기에 생기는 일

## 3단계 · 점수 매기기
후보마다 1~5점. 합계가 높은 것을 고르되 **새로움 2점 이하는 점수와 상관없이 뺀다.**

| 기준 | 5점이면 |
|---|---|
| 지금성 | 오늘~2주 안에 검색이 오르거나 마감·시행이 있다 |
| 수요 | 서로 다른 갈래의 신호가 2개 이상 겹친다 |
| 빈틈 | 그 검색어로 상위 글 제목 3~5개를 훑었을 때 우리가 더 줄 것(숫자·개인화·실행 디테일·원리)이 분명하다 |
| 수익 맞춤 | 광고 수익 = 검색량·오래 읽힘, 판매 수익 = 사기 직전의 질문, IT/AI = 전문성·다시 찾아옴 |
| 새로움 | 최근 원고와 대상·각도·글 틀이 모두 다르다 (아래 4단계) |
| 사이트 맞춤 | 넣을 사이트·카테고리 컨셉에 그대로 들어간다 |

## 4단계 · 반복 막기 (꼭 지킨다)
먼저 지난 원고 제목을 모두 본다: 원고 폴더(`콘텐츠/블로그_카페/포스팅자동화/원고/`)에서 `^# \[원고\]` 를 Grep 하면 한 번에 나온다. 날짜가 필요하면 그 원고의 `git log -1 --format=%ad --date=short`.
- **같은 대상은 21일 안에 다시 쓰지 않는다.** 대상 = 제품·제도·행사·대회·작품·에러 종류·소재(정전기, 온수매트, 스키장 개장 등). 예외: 큰 변화(새 발표·숫자가 크게 바뀜·마감 임박)가 있을 때만 '바뀐 것' 각도로, 기획표에 지난 T번호와 바뀐 점을 적는다.
- **글 틀을 돌린다.** 장부의 소분류 횟수를 보고 그 중분류에서 적게 쓴 소분류를 먼저 고른다. 같은 중분류에서 같은 소분류를 세 번 연속 쓰지 않는다.
- **제목 틀을 돌린다.** 최근 7일 제목과 짜임이 같은 제목(예: "~해도 되나", "뚜벅이 당일치기 코스", "~ 해결 (Node.js 22, 윈도우 11)", "~ 결말 해석", "언제? 작년 ○○으로 보는")은 하루에 1편, 같은 중분류에서는 주 1편까지.
- **계절 소재는 하루 2편까지.** 겨울 난방·건조·정전기·결로처럼 같은 계절 소재가 여러 분류에 겹치지 않게 한다.
- **탐색 몫: 하루 2편 이상은 최근 30일에 없던 영역.** 안 써 본 소분류, 새 독자층, 새 소재군 중 하나. 기획표에 '탐색'이라고 표시한다.
- **커스텀 글과 겹치지 않는다.** 장부의 [커스텀] 원고(고정 주제: 공모주·청년신혼 정책 등)가 다루는 것은 일일 슬롯에서 피한다.
- **마지막 점검:** 정한 주제를 한 줄씩 나란히 놓고 대상·독자·글 틀·제목 짜임이 겹치는 쌍이 있으면 하나를 다음 후보로 바꾼다.
- 오늘 신호가 지금 분류·소분류로는 담기 어려운 주제를 계속 가리키면 기획표 끝에 '분류 제안'으로 한 줄 남긴다 (메인이 `writing.md` '분류를 고치거나 더할 때'로 판단한다).

## 5단계 · 기획표 쓰기
파일: `콘텐츠/블로그_카페/포스팅자동화/주제기획/<날짜>.md` (그날 두 번째 기획이면 `<날짜>_2.md`).

```
# 주제 기획 · 2026-10-23

## 오늘의 신호
| 말 | 갈래 | 출처 | 날짜 | 맞는 분류 |
(15~30줄)

## 슬롯
### T103 · 광고 수익 > 금융·시장 > 일정 달력
- 사이트 › 카테고리:
- 주제:
- 각도 (한 문장):
- 독자 · 검색어:
- 왜 지금: (신호 갈래 + 출처 + 날짜)
- 우리가 더 줄 것: (상위 글이 놓친 것)
- 반복 점검: (가장 가까운 지난 원고 T번호와 다른 점, 없으면 '없음') · 탐색이면 '탐색'
- 점수: 지금성 · 수요 · 빈틈 · 수익 · 새로움 · 사이트 = 합계
- 다음 후보: (작가가 바꿔야 할 때 쓸 후보 1개, 한 줄)

## 오늘 배운 것
- 새로 연 영역 · 피한 반복 · 잘 나온 신호 갈래와 안 나온 갈래 (2~3줄. 프롬프트 최신화가 읽고 이 문서를 고친다)
- 분류 제안: (있을 때만)
```

## 6단계 · 돌려주기
기획표를 저장하고 메인에게는 이것만 돌려준다 (신호·조사 내용은 붙이지 않는다):
```
기획표: 콘텐츠/블로그_카페/포스팅자동화/주제기획/2026-10-23.md
T103 · 금융·시장 > 일정 달력 · <주제> · <사이트 › 카테고리>
T104 · ...
```
git 커밋·push 는 하지 않는다 (메인이 원고와 함께 올린다).
