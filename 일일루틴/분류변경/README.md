# 분류 변경

글쓰기 루틴이 글 분류(대 › 중 › 소 › 하위)를 고치거나 더할 때 남기는 파일. 서버는 git pull 로 받아,
글 분류·일일루틴 화면을 열 때 아직 반영 안 한 파일만 DB 에 반영한다 (`workspace/apps/blog_types/changes.py`). 같은 파일은 한 번만 반영된다.

## 원칙
- 대분류는 고치지 않는다. 지우지 않는다 (지우는 건 사람이 화면에서).
- 이름 고치기가 먼저: 그 아래 글을 대부분 담을 수 있는 공통적인 말로.
- 새로 더하기는 정말 새로운 주제일 때만. 하루 한두 건 이내.
- `reason` 에 왜 바꿨는지 한 줄.

## 파일
`일일루틴/분류변경/YYYY-MM-DD_짧은이름.json` — 이미 있는 파일은 고치지 말고 새 파일을 만든다.

```json
{"date": "2026-10-17", "reason": "AI 요금제 비교 글이 늘어 소분류를 더함", "changes": [
  {"op": "add", "parent": "IT/AI > AI 도구·활용", "name": "요금제·무료 범위 비교"},
  {"op": "add", "parent": "광고 수익 (조회수)", "name": "새 중분류", "direction": "사람들이 찾아오는 이유", "question": "검색창에 치는 질문"},
  {"op": "rename", "path": "광고 수익 (조회수) > 정책·내 돈", "to": "정책·지원금·내 돈"}
]}
```

- 경로는 ` > ` 로 잇는다. 중분류는 이름만 (기호를 붙여 `B 정책·내 돈` 처럼 써도 된다).
- `add` 의 parent 가 대분류면 중분류, 중분류면 소분류, 소분류면 하위가 생긴다. 중분류 기호는 서버가 다음 글자로 붙인다.
- 반영 결과는 서버의 '분류 변경 기록'(관리화면)에 남는다. 못 찾은 경로는 건너뛰고 그렇게 적힌다.
