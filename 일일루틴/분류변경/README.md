# 분류 변경

글쓰기 루틴이 글 분류(사이트 › 소재)를 고치거나 더할 때 남기는 파일. 2026-10-22 부터 글 분류 = 사이트 > 고정 소재 (소분류 없음). 서버는 git pull 로 받아,
글 분류·일일루틴 화면을 열 때 아직 반영 안 한 파일만 DB 에 반영한다 (`workspace/apps/blog_types/changes.py`). 같은 파일은 한 번만 반영된다.

## 원칙
- 대분류(사이트)는 고치지 않는다. 지우지 않는다 (지우는 건 사람이 화면에서).
- 사이트 안의 소재(중분류)는 자유롭게 고치고 더해도 된다 (2026-10-22 사용자). 이름은 짧은 키워드로, 늘리기보다 합치기·고치기가 먼저.
- 소분류는 두지 않는다 (글 틀은 기획표에서 정한다).
- `reason` 에 왜 바꿨는지 한 줄.

## 파일
`일일루틴/분류변경/YYYY-MM-DD_짧은이름.json` — 이미 있는 파일은 고치지 말고 새 파일을 만든다.

```json
{"date": "2026-10-25", "reason": "공연·콘서트 예매 소재가 며칠째 '그 외'로 나와 소재를 더함", "changes": [
  {"op": "add", "parent": "black_lukey", "name": "공연·티켓팅", "direction": "글쓰기 컨셉 한 줄", "question": "검색창에 치는 질문"},
  {"op": "rename", "path": "눈잎 > 해외 여행", "to": "동남아·해외 여행"}
]}
```

- 경로는 ` > ` 로 잇는다. 중분류는 이름만 (기호를 붙여 `B 정책·내 돈` 처럼 써도 된다).
- `add` 의 parent 는 사이트(대분류)로 쓴다 — 소재가 생긴다. `direction` 은 글쓰기 컨셉이다. 기호는 서버가 다음 글자로 붙인다.
- 반영 결과는 서버의 '분류 변경 기록'(관리화면)에 남는다. 못 찾은 경로는 건너뛰고 그렇게 적힌다.
